# embarch.md: changelog archive

- 2026-08-04 — Two implementation passes closing open items on both sides of the Core↔dev-bench hop (§3 rows for `embarch-core` and `embarch-dev-bench` updated). `embarch-core` gained dev-bench serial-port auto-detection (`dev_bench.rs`): SEGGER's VID `0x1366` plus a normalized product-string/serial-number/USB-interface heuristic, exposed as a fifth endpoint `GET /dev-bench/port` and a `detect-dev-bench` CLI subcommand — closing the open item `embarch-dev-bench/design.md` §4 had been holding for it. `embarch-dev-bench`'s `ble_bridge_real.c` went from `BleAdvertise`-only to the full `Action`/`GattOperation` surface (connect as central or peripheral, GATT discovery + read/write/notify/indicate/subscribe/stream-capture), which also fixed a latent build break (`BT_LE_ADV_CONN_NAME` no longer exists in Zephyr 4.x). The `nordic` workspace was then fetched and built for the first time (NCS v3.4.0), compiling that BLE code for real nRF54L15DK hardware and correcting two factual errors in `embarch-dev-bench/design.md`'s own decisions along the way (sysbuild is always used under NCS 3.4; `CONFIG_BT_MAX_CONN`'s default here is 2, and forcing it to 1 silently zeroes the central role's link slots). Still not hardware-validated: Core's detection has never seen a real J-Link, and no board has been flashed. Full detail in both sub-projects' own changelogs.

- 2026-07-30 — `embarch-dev-bench` gained its first real code (§3 row updated): a shared `app/` C application (COBS+postcard `DevBenchMessage` encode/decode hand-written in C, a stubbed `study_ffi.c`, and a `ble_bridge` split into `_real`/`_stub` implementations per design decision 16), a buildable `native_sim` workspace, and a `nordic`/nRF54L15DK workspace skeleton (west manifest only — not yet run against real hardware). Implementation research surfaced a real design gap: the nRF54L15 SoC has no USB device peripheral, so the original USB-CDC-ACM Core link and custom-VID/PID auto-detection (design decisions 6/12) were revised to a plain UART over the nRF54L15DK's existing on-board J-Link VCOM, with auto-detection moving to `embarch-core` matching SEGGER's VID instead. `embarch-study-designer` also gained the `DevBenchMessage::LogLine` variant and `HelloAck.firmware_version` field this work had been waiting on (schema version 1 → 2), closing an open item from its own previous pass. Full detail in both sub-projects' own changelogs.
- 2026-07-29 — `embarch-dev-bench` moved from a placeholder to an actual scoping pass (§3 row updated): repo created empty at [gabrieltetar/embarch-dev-bench](https://github.com/gabrieltetar/embarch-dev-bench); Zephyr locked in as the one common RTOS across every vendor/board it'll eventually target (not a custom multi-SDK abstraction), with one shared application spanning multiple vendor-specific west workspaces to resolve the "a west manifest pins one Zephyr revision" constraint against vendor forks like Nordic's nRF Connect SDK. First board: nRF54L15DK. Full detail in `embarch-dev-bench/design.md`.
