# embarch suite decisions: tooling and checks

**Status:** active, 2026-09-12.

How the suite's formatting and CI checks are run, and what a green one covers.

Index: [../decisions.md](../decisions.md). Suite overview: [../../embarch.md](../../embarch.md).

## 1 — `rustfmt` is not enforced, and nobody runs `cargo fmt`

*Decided 2026-09-06. Moved here verbatim from [embarch.md](../../embarch.md) §5 on 2026-09-10 by `tasks/suite/008`, only the two relative link paths re-based for this file's depth. Three rounds of decision text had landed in that bullet — `suite/006` wrote it, `suite/007` added the two-spellings analysis, `api/024` falsified one of its sentences — which is why leg 017 asked that the next thing landing there force the question rather than be absorbed too.*

**`rustfmt` is not enforced, and nobody runs `cargo fmt`** (decided 2026-09-06). No gate checks formatting — not [the protocol](../../../embarch-fleet/protocol.md) §10, not any repo's CI — and none is being added yet. **This is a sequencing decision, not a verdict on formatting**: adopting is worth doing, doing the expensive half first is not. Measured across the six Rust crates on that date: `cargo fmt` would rewrite **87 files, 1,289 hunks, 1,947 existing lines**, largest `embarch-api` and `embarch-study-designer`, 24 files each. `embarch-outpost` and `embarch-dev-bench` have no `Cargo.toml`, so are not in scope. **Formatting without a check decays**: `embarch-umbrella` went 172 → 212 hunks over eleven commits in thirteen hours, monotonically, on 2026-09-05 — so the format-the-world commit buys nothing durable until the check exists, and **the check that makes it stick belongs in §10, which is the repo owner's alone.** The `git blame` objection is *not* the reason: `.git-blame-ignore-revs` answers it cheaply, and nothing similarly cheap answers decay. **Reversal condition: the moment a formatting check is added to §10 or to any repo's CI, the format-the-world commits land in the same sitting — one per crate, separate from any behaviour change.** **When that check is wired, neither spelling is simply right, and getting it wrong fails silently.** A cargo command at a repo root reaches **the packages it selects**, and a path-dependency crate that is not a workspace member is not one — the same blind spot for `fmt`, `clippy --all-targets` and `test` alike. Bare `cargo fmt --check` used to miss `embarch-api/crates/embarch-core-client` entirely — 6 files, 43 hunks — passing green with them unformatted. `cargo fmt --all --check` reaches those, and also reaches sideways through `path = "../…"` into sibling **repos**, which is why a naive per-repo `--all` sum triple-counts `embarch-study-designer` and `embarch-topology`, and why a per-repo gate spelled `--all --check` fails `embarch-api` on another repo's files. **The check must cover every crate inside the repo and nothing outside it, and which spelling does that depends on the repo's manifest**: scope `--all --check` to the repo's own tree, or run `--check` once per in-repo crate. **Workspace membership is what actually closes it**, and `embarch-api` took that route on 2026-09-06 for the clippy instance ([decision 56](../../embarch-api/decisions/tests.md)) — so there, bare `--check` and `-p embarch-api -p embarch-core-client --check` now agree on **24 files, all in-repo** (18 plus the sub-crate's 6), where `-p` previously *refused*. **`--all` is unchanged by that**: still 57 files, **33 of them outside the repo** — `embarch-study-designer` 24, `embarch-topology` 9 — and the `embarch-topology` reach is *transitive*, through `embarch-core-client`, so dropping the direct sibling dep would not close it. **The two subcommands do not read the same manifest field** — bare `cargo fmt` follows `members`, bare `cargo clippy --all-targets` follows `default-members` — so a manifest carrying only `members` fixes `fmt` and leaves `clippy` blind. **No other repo in the suite is behind this**: `embarch-api/crates/embarch-core-client` is the suite's only nested in-repo crate, swept 2026-09-06 (`tasks/doc/017`). The trap it closes was open until 2026-09-06: a worker that types `cargo fmt` gets a diff dozens of files wide that `check-ownership.py` allows — a worker owns its code repo's whole tree — and nothing it read said not to. Closed in the fleet's own instructions rather than by a gate, the worker agent definition and [the protocol](../../../embarch-fleet/protocol.md) §5's contract both forbidding the command (`tasks/doc/014`) — an instruction, not a mechanism, and the reversal condition above is still what buys one.

## 2 — `embarch-outpost` gets a host-only CI workflow, and a green check there covers strictly less than a local run

*Decided 2026-09-11 by `tasks/suite/028`, announced under [ops](../../../embarch-fleet/ops.md) §4 (`ts 1789182061.785499`), window closed with no objection. Suite-scope rather than `embarch-outpost`'s own, because a CI position is a cross-repo consistency call and [embarch-outpost/open.md](../../embarch-outpost/open.md) said so in as many words — the item survived because the only doc that noticed it was also the one that correctly refused to decide it.*

**`embarch-outpost` now has `.github/workflows/host-tests.yml`, running the two host-only legs of `tests/run-all.sh` — `decoder_unit.py` (31 tests) and `vocab_check.py` (11 record kinds, 8 header flag bits) — on push to `main` and every PR.** It was the suite's only code-bearing sub-project with no CI at any commit, so `decisions/testing.md` decision 22's toolchain-free leg ordering — fixed precisely because it had been wrong — ran only when a human remembered.

**The workflow does not invoke `run-all.sh`, and that is the load-bearing detail.** That script is one file under `set -euo pipefail` whose west guard is spelled `WEST="${WEST:?set WEST to a west executable}"`, so on a runner with no toolchain it runs the host legs and then **exits non-zero**: invoking it in CI could never go green, however correct its leg ordering. The workflow therefore lists the host legs itself. **The cost is real and stated in the workflow's own header: a new host-only leg added to `run-all.sh` is not picked up automatically and must be added in the same commit.**

**Two things are deliberately uncovered, and the file says so where anyone reading a green check sees it.** The three Zephyr legs (ztest unit, module-off compile, `native_sim` end-to-end stream) need `west`, a Zephyr checkout and the SDK; provisioning those is real cost and a real maintenance surface for a repo whose tests otherwise run by hand; weighed and not taken. **The cross-decoder leg is excluded for a stronger reason**: it compares this repo's decoder against `embarch-core`'s over committed fixtures, which needs the sibling repos checked out beside it, so here it would `SKIP` on **every** run — *a step unable to fail for the reason it was added*, the same objection [embarch-study-designer/open.md](../../embarch-study-designer/open.md) raises against a cross-compile job for the FFI staticlib ahead of its toolchain. A permanent skip is worse than an absence: it reads as coverage. `vocab_check.py`'s own sibling half skips the same way but is kept: the leg around it still checks the local half against `src/outpost_priv.h`.

**Why not "no CI, recorded as a decision with a trigger"**, which the task named as legitimate: two host legs needing nothing but `python3` were already written, already green, and already the half the repo's history records as silently unreached. Declining them would have been declining the cheap half to avoid the expensive one.

**Reversal condition: the moment `embarch-outpost`'s Zephyr tests can be built from a provisioned runner** — a container image or an SDK-provisioning action someone will maintain — **the three Zephyr legs join this workflow and the exclusion note above shrinks to match.** Until then a green check honestly reads as "the host decoder and the record vocabulary agree with the header", and nothing about the module as Zephyr builds it.
