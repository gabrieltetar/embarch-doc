# embarch suite decisions: where a capability's implementation lives

**Status:** active, 2026-09-13.

Which sub-project holds a computation that more than one path needs, when the answer is not obvious from what the computation is *about*.

Index: [../decisions.md](../decisions.md). Suite overview: [../../embarch.md](../../embarch.md).

## 4 — The outpost's own answer is computed once, in `embarch-core`, because Core is the only component on both paths *and* in the release archive

*Decided 2026-09-13 by `tasks/suite/018`, announced under [ops](../../../embarch-fleet/ops.md) §4 (`ts 1789348880.412099`), window closed unanswered at 19:51 after four polls. Suite-scope because it binds `embarch-core`, `embarch-ui` and `embarch-api` and belongs to none of them. **This decision names the home; it does not move the code** — that is queued separately.*

**The property being bought:** an agent can obtain an outpost capture's **per-subject load shares and its coverage line** without re-implementing the timeline, and exactly one implementation of that timeline exists in the suite. [`embarch.md`](../../embarch.md) §5 already requires every hardware-facing capability to be reachable both by an agent and by a human, *"converging on the same underlying modules"*; [`embarch-outpost`'s spec](../../embarch-outpost/spec.md) §1 states the capability as *"the study passed, but what was the CPU doing while it did?"* Today a human gets that answer and an agent gets a CSV that has run to 225,606 rows.

**The home is `embarch-core`, and the argument is an intersection of two constraints that already exist rather than a preference.** Core is the only component that is **on both paths** — the agent reaches it through `embarch-api`, the human reaches it through `embarch-ui`'s existing Core client, and neither needs a new dependency direction — **and in the release archive**, which a fresh `embarch setup` installs. Core also already holds the decode half — `src/outpost_manifest.rs` verifies the manifest, unwraps cycles and renders the CSV ([`embarch-core/spec.md`](../../embarch-core/spec.md) §2), and it **refuses a manifest whose `record_layout_version` differs from the shared crate's**. So this is adding the analysis beside a decode that is already there and already pinned, not standing up a second decoder.

**What does not move: everything that exists in order to draw.** `bin_window`, `BinnedLane`, `BinRun`, `StepBand` and the `TraceView` payload shape are chart geometry, and [`embarch-ui` decision 18](../../embarch-ui/decisions/trace-transfer.md)'s shape — the aggregation runs on the server and the view asks for the window it is about to draw — **is preserved, not reopened.** What changes is which server holds the decoded view. The browser's contract is untouched.

**Why not [`embarch-study-designer`](../../embarch-study-designer/spec.md), which is the reflex answer for anything two consumers share.** Its §1 membership rule admits *"anything every consumer must agree on byte-for-byte or column-for-column"* — the wire and the column vocabulary, both of which are already there and stay there. **A load-share computation is not a thing consumers must agree on; it is a result one of them produces**, so it fails the rule that admits the wire and the column vocabulary. Its §2 **allocator-free end to end** invariant is the second reason, since the crate links into bare-metal C firmware — though the `std`/`alloc` feature makes that one negotiable, which is why it is not the load-bearing half of this argument. **§2's "never interprets a payload" is *not* offered as a third reason**: that invariant is about raw wire bytes, and this analysis runs over already-decoded CSV columns. Reaching for it would be the stretch, and the exclusion does not need it.

**Why not leave it in [`embarch-ui`](../../embarch-ui/spec.md) and give it an agent route**, which is the cheapest move and was rejected on one fact: `assemble-suite.yml` ships three binaries and `embarch-ui` is not one of them, and **whether it belongs there is explicitly undecided and explicitly not that repo's call** ([`embarch-ui/open.md`](../../embarch-ui/open.md)). An agent-reachable capability that exists only on a machine where somebody separately built the UI does not satisfy §5; it restates the gap one layer up. It would also need `embarch-api` to reach `embarch-ui`, a direction the suite does not have.

**What this decision is worth, measured:** [reversals row 86](../../reversals/rows-73-92.md). A wire change added two clock columns; the UI parsed six columns, never read them, and timed every span by its *frame's* arrival — **the outpost's own drain thread reported at 78.1% of measured extent against a true 1.6%, a 46× error on the single number the next session was briefed to reduce**, plus 4,286 of 4,955 spans called below-resolution when none were. **A second, independent half of the same incident was in Core**, whose manifest was latched only when the decode loop reached the header frame, so 488 rows rendered nameless inside a stream whose index said named. One wire change, two independent host failures, because there were two independent hosts.

**That row is also the honest limit of this decision, and it cuts against it.** Core's half of row 86 drifted too, so *being Core* is not what makes an implementation correct — being **one** implementation, pinned to the vocabulary it decodes, is. The pin on the UI side already exists and is kept: [`embarch-ui` decision 10 (trace)](../../embarch-ui/decisions/trace-view.md) checks the rendered CSV's column list against the shared crate's own header and **refuses if it differs** — cited with its disambiguator because that repo carries three different decision 10s, one each for routing, trace and chart, and a bare `embarch-ui decision 10` resolves to whichever the reader opens first. Whatever holds the analysis inherits that obligation.

**Reversal condition: `embarch-ui` being admitted to the release archive.** That dissolves exactly half of the argument above — the archive half — and nothing else; the agent path still would not reach a computation living in the UI, and the §5 requirement would still be unmet. So an archive decision is a reason to re-read this one, not a reason to reverse it. **The decision is genuinely reversed only if the suite acquires a host-side analysis crate that both Core and the UI depend on**, which is the third option considered here and was rejected on cost rather than on principle.

### One correction to the task that raised this, recorded because the citation resolves

`tasks/suite/018` quoted [`embarch-ui/open.md`](../../embarch-ui/open.md)'s *"a direction the suite has nowhere"* as the repo recording that its trace analysis is structurally unreachable from the agent path. **That sentence is from the reflash-selector bullet and is about `run_study --reflash` orchestration** — [`embarch-ui` decision 11](../../embarch-ui/decisions/study-designer.md), whose body carries the phrase verbatim — not about trace analysis. The conclusion it was cited for happens to hold on other grounds — stated above — but it was not the repo's own statement of it. The task also gives `trace.rs` as 3,892 lines against an actual **4,126**, with every cited line number moved by 20–30.
