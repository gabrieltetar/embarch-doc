# embarch-umbrella decisions: running the agent's container

**Status:** active, 2026-11-25.

What starts, stops, checks and enters the container that decisions 62 to 66 render. Index: [../decisions.md](../decisions.md). Design: [notes/hil/12-prevention.md](../../notes/hil/12-prevention.md), "A person's act".

### 67 — `embarch agent up | down | status | shell` act through one `ContainerRuntime` adapter, and run what `init` recorded, never a vector of their own

**This is the plan's recommended shape (plan choices 5, 6 and 9), not an owner-struck one; the owner may strike any of the three.** It extends 62 to 66, whose bodies are untouched. `src/agent_run.rs`: the trait `ContainerRuntime` (`build`, `image_exists`, `volume_create`, `run`, `stop`, `rm`, `exec`, `inspect`) over a `Process` seam; `CliRuntime` is Docker or Podman by its binary alone (`docker()` and `podman()` constructors, no second type, because no test showed a verb that differs). Every test runs against a `FakeProcess` that records each argv; no container runtime ran.

**`up [<name>]`** names the agent by argument, by the registered repo holding the current folder, or as the only one registered. It reads `container.toml` and **refuses before any side effect** when the vector no longer hashes to its record (a hand edit), when `forbidden_findings` names anything, when the Containerfile no longer hashes to the recorded image tag, or when the container already exists (`down` first). Then: `build` only when no image carries the tag; `volume create` (idempotent on both runtimes, so "once" is the runtime's); Core's address through `core_addr_from_container` (the WSL gateway from `ip route show default` through `parse_default_gateway`; the bridge gateway from `network inspect`), written to `<definition>/start/core-addr`; then `run` with the **recorded vector, `<core-addr>` filled in**, and `/etc/embarch-agent/entrypoint-root.sh /etc/embarch-agent/entrypoint-agent.sh` after the image (settling 66's open line). **The vector is not re-rendered from a plan:** no plan is stored, only the vector and its hash, so `up` runs what the person's `init` wrote and the hash is the proof it was not changed.

**The build context is staged** under `<exchange>/build-context/`: the Containerfile and each `requirements/<name>` it copies, re-read from the workspace and held to the hash the Containerfile's comment records, so a changed file is refused with "run `init` again" (settling 64's open line on the context). **The root script (63) reads Core's address from `/etc/embarch-agent/start/core-addr`** when rendered with the placeholder, which is how `init` renders it; a definition folder written before this unit keeps its old `entrypoint-root.sh` (`init` never overwrites a differing file) and needs it deleted and `init --container` run again.

**`down`** stops (when running) and removes; the volume and the exchange folder stay. **`status`** names each finding and exits `1` on any: `definition` (hand edit), `vector` (the scan), `containerfile`, `fingerprint` (the definition folder's copy against `core-fingerprint` in Core's data directory, when both exist; **never the agent's writable `embarch/` seed**, a test holds that), `running`, then through `exec` as the agent user `core` (Core answers at the recorded address) and `firewall` (`192.0.2.1:443`, off the list, must not). **`shell [--claude]`** is `exec -it -u agent -w /work/<repo folder>` into `bash` or `claude`. **With no runtime binary on `PATH`, every verb refuses** and names the install.

**Assumed or from memory, to be checked:** the host-side fingerprint is `<Core data dir>/core-fingerprint`, "beside the token file" read as the machine-wide one; `network inspect`'s JSON is read by key name (`gateway`, case-insensitive) because Docker and Podman spell it differently, and Podman's default network is called `podman`; `image inspect` exits non-zero for a missing image on both; `exec` as `agent` reaches `nc`. **Unverified:** nothing here ran against a runtime.

**Hardware-free debt, for the owner's first container:** install Docker or Podman, `embarch init --container` in a repo, `embarch agent up`, then `embarch agent status` (every line `ok`), `embarch agent shell` (a shell in `/work/<folder>`, `claude` starting), `docker inspect embarch-agent-<name>` against the vector in `container.toml`, `embarch agent down` (volume and exchange folder still there). Read what the build says about the SDK URL and `setup.sh` (64), and whether `nc` reaches Core from the agent user.

**Open:** a changed `Containerfile` template needs `init` run again and a new image, and nothing removes the old one; a stopped container is removed by `down` only; `status` does not probe other ports on Core's host (63); Windows hosts and `docker-desktop` run the same code unverified.
