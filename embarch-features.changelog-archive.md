# embarch-features.md: changelog archive

- 2026-08-26 — **Two rows added and the naming row amended, after the GATT extraction turned out to have been reading two files and missing a third.** The extraction row is the notable one: it records a capability that had been quietly incomplete rather than one that is new, and the measurement that decided its exclusion rule, because "scan the repo" and "scan the repo the way the repo defines itself" produce three services and six respectively on the same real checkout. The picker row and the naming amendment are the human half of the same pass.
- 2026-08-26 — BLE bridge row extended with the selective monitor actions, and a new row for per-characteristic GATT capture (`StreamSource::GattNotify` taps decoded by a declared struct layout, plus the auto-declared uncapped transcript). Both marked shipped-but-not-yet-run-on-hardware, which is exactly what they are: every layer is implemented, tested and deployed, and no real notification has gone through the path yet.
- 2026-08-26 — **The MCU-load-tracing and DUT-signal-link rows both updated from a bench attempt rather than a build** (Milestone 7 Phase E). Tracing moves from "never having put a byte through a real UART" to the same thing said more precisely: the module is now integrated into the real reference-dut firmware, pinned in that repo's `west.yml`, and **flashed onto real silicon where it runs** — the instrumented DUT still advertises, connects and serves GATT — and the byte still has not crossed, because the DUT's trace pin is not wired to anything the host can read. The signal-link row's caveat changes shape for the same reason: it used to say no bridge exists, and the accurate version is that one is plugged in and is not connected to the pin. Also added: the Trace view's **load repartition**, which is what "understand where the CPU's time went" actually resolves to, built against the simulator capture for want of a real one.
- 2026-08-26 — **The MCU-load-tracing row gained the sentence that changes what the feature is:** the DUT carries no clock, and `embarch-core` stamps each frame as it arrives ([embarch-outpost/design.md](embarch-outpost/design.md) §3 decisions 4, 17). The status word does not move — it was already "built, never having put a byte through a real UART" and still is — but what a built trace *can say* changed: a frame is the resolution, so this feature counts ISR entries and no longer times them, while gaining an axis shared with every other stream in a study. Recorded here rather than only in the design doc because the row's parenthetical is the whole description a reader of this table gets.

Recorded here only so the absence of a row is a decision rather than an oversight.

Building it also fixed two pre-existing defects in `embarch-ui`'s Debug tab that are not separately listed features — ANSI escapes from Core's logfile rendered as garbage, and the log SSE stream replaying its last batch to every new subscriber.
