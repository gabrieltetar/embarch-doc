## HTTP

**HTTP on `127.0.0.1:4891`**, bearer `~/.config/embarch-desk/desk-token` (generated on first run) on every route but `GET /health` and `GET /oauth/linear/callback`:

| `GET /view` | Cards (visible work items with tiles, PRs, sessions, bench), **`hand`** — every open tile not covered, on every desk but an archived card's, the viewed desk's first then oldest first, each with `item_id`, `key`, `item_title`, `desk`, `desk_id` (57; it replaced `elsewhere`) — connector status, ignore list. A tile carries `covered` and `folded_into`, and its `lines` include those of tiles folded into it (58). ### Added for `embarch-chat`

The route table moved verbatim to [interfaces/chat-routes.md](interfaces/chat-routes.md): every route takes the desk's bearer token; additions only; `?desk=` takes a desk's id or its name.

**The caller's desk** (77). The desk's client (MCP server, hook, CLI) sends `x-embarch-session: <CLAUDE_CODE_SESSION_ID>` and `x-embarch-cwd: <its folder>` on every call when it runs inside a Claude Code session; `embarch-api` sends both on `GET /desks`. `/linear/mine`, `/linear/open`, `/linear/search`, `/pickup`, a new issue's default team and Project on `/drafts` (a `session_id` in the body stands in for the header) and `GET /desks`' `session` follow that session's desk: its folder's, else its work item's, else none, which is unscoped. A call with no session header works on the UI's desk. **`desks.json`** beside the state holds `{"desks": [...]}`, every desk, rewritten on start and on every desk saved or deleted; the old `open-desk.json` is deleted on start.

## The plugin

**The plugin** (`plugin/` in the repo, listed in the suite's `embarch` marketplace in `embarch-umbrella`, `embarch-promptu` decision 20): hooks on SessionStart, UserPromptSubmit, PostToolUse, Notification, Stop and SessionEnd, all running `embarch-desk hook`; a `desk` skill; and an MCP server `embarch-desk mcp` that is **agents' one access point to Linear and Harvest** ([decision 29](decisions.md)) — work items (`desk_whoami`, `desk_work_item`, `desk_set_work_item`, `desk_add_line`, `desk_list_items`, `desk_create_item`, `desk_link`, and `desk_add_repo` on a suite desk), Linear (`linear_get_issue`, `linear_my_issues`, `linear_search`, `linear_teams` — each account's label and its teams, never a token, `linear_set_status`, `linear_draft_comment`, `linear_draft_issue`, `linear_draft_edit` — 75), Harvest read-only (`harvest_entries`, `harvest_projects`) the manual timer (`desk_timer_start`, `desk_timer_stop`), and desks (`desk_list_desks`, naming the desk this session works on; `desk_add_desk_note`, a standing note on the session's desk, which every SessionStart in its repos then carries, 74). **A commit becomes a tile line** when a PostToolUse `Bash` command contains `git commit` and HEAD is new; **an `embarch-api` build, flash, bootload, reset or study call becomes bench activity** ([decision 22](decisions.md)).

**Notes** (48–55). A note is `{id, ts_ms, session_id, kind, text, source_path}`; kind `memory` is a captured memory file, one per `source_path`, its versions kept. `desk_work_item` returns the brief for the calling session's item, then the desk notes `GET /sessions/{sid}` gives (74), and the SessionStart brief names it as the way to everything about the item; `desk_add_line` takes a `kind`. **Capture** (52): a PostToolUse `Write`, `Edit` or `MultiEdit` whose `file_path` is under `~/.claude/projects/*/memory/` and is not `MEMORY.md` files the file's text after the write on the session's item — held until the session has one, as lines are. **Import** (54): once, on the first start that has notes. **Harvest** (50): the polish reads that day's notes of every kind.

## Connectors and CLI

**Connectors** (pasted tokens, [decision 16](decisions.md)): Linear personal API key per workspace (GraphQL), or, for a workspace that gives no key, a sign-in through Linear's MCP server whose account keeps `[linear.mcp]` (`client_id`, `refresh_token`, `expires_ms`) and is answered through the server's tools (68); Harvest personal access token (REST v2, every account it reaches); GitHub token or the user's `gh` login (REST; PR search by key, within the desk's repos when it names some). A kind is `linear`, `harvest` or `github`; a `[[slack]]` table saved before decision 66 still loads, is never read and is written back on save.

**CLI:** `serve`, `hook`, `mcp`, `service install|uninstall|status` (a systemd user unit), `connect <kind> <label>` (token on stdin; `connect linear <label> --mcp` prints the sign-in link instead and waits for the browser), `disconnect`, `ignore list|add|remove`, `desks` (the UI's marked `*`, and inside a session the one it works on), `status`.
