## HTTP

**HTTP on `127.0.0.1:4891`**, bearer `~/.config/embarch-desk/desk-token` (generated on first run) on every route but `GET /health` and `GET /oauth/linear/callback`:

| Route | What |
|---|---|
| `POST /hook` | A hook's stdin JSON verbatim; returns `{context}` for SessionStart/UserPromptSubmit |
| `GET /view` | Cards (visible work items with tiles, PRs, sessions, bench), **`hand`** — every open tile not covered, on every desk but an archived card's, the viewed desk's first then oldest first, each with `item_id`, `key`, `item_title`, `desk`, `desk_id` (57; it replaced `elsewhere`) — connector status, ignore list. A tile carries `covered` and `folded_into`, and its `lines` include those of tiles folded into it (58). An approved tile with time since its ✓ is in the hand with `more: true`: `hours` is what ✓ adds, `logged_hours` the item's Harvest hours that day, `entry_hours` the entry's, `lines` those since the ✓, `note` the draft for the entry, `sent_note` what it holds (64) |
| `POST /items`, `/items/{id}/pin`, `/archive`, `/link`, `/status`, `/launch`; `GET /items/{id}/states` | Create from issue key or title; pin; archive; link issue or repo; move Linear status; open in VS Code |
| `GET /sessions/{sid}`, `POST /sessions/{sid}/assign`, `/line` | What a session is on; put it on an item (an `issue_key` no workspace has is a 404 naming it and the workspaces asked, Linear unreachable a 502; no card is made) (or untrack it); add a milestone line, on the session's item or, with `item` (an issue key or item id, any desk), on that item's tile for today; an unknown `item` is a 404 naming it and writes nothing (78); any other unknown field in a line body, here or on `POST /tiles/{id}/line`, is a 400 naming it (85); `DELETE /sessions/{sid}/line/{nid}` takes back a line that session wrote while its tile is open: 403 for another's, 404 for an unknown id, 400 once the tile is sent (85) |
| `PATCH /tiles/{item@date}`; `POST …/line`, `/polish`, `/approve`, `/discard`, `/fold` | Edit note, hours (`null` clears a typed override back to computed, 61), Harvest target; Claude drafts note and target; ✓ to Harvest, linked to the item's Linear issue (63); ✕; `{"into": <date>}` folds it into the item's open tile that day (58); 400 if `into` is not a real date later than the tile's, and every tile route 400s on an id whose date is not `YYYY-MM-DD` (60). | `GET/POST /connectors`, `DELETE /connectors/{kind}/{label}`; `GET/PUT /ignore`; `POST /sync` | Accounts (labels only, never tokens); the ignore list; refresh now |
| `POST /linear/signin`, `GET /linear/signin/{state}`; `GET /oauth/linear/callback` | A Linear sign-in through Linear's MCP server (68): `{"label"}` → `{"url","state"}`, the link for the browser; then `{"status","label","detail"}`, `status` `waiting`, `ok` (the account's check) or `failed`, 404 after 10 min. The callback is where Linear sends the browser back, **without the bearer**: a state the desk handed out, used once, keeps the account and answers a small page |

| `POST /drafts`, `PATCH /drafts/{id}`, `POST /drafts/{id}/send`, `/discard`; `POST /timer/start`, `/timer/stop` | Agents' comment, issue and edit drafts, sent only from the tab or at once on a direct-write desk; a comment draft takes `reply_to` and `replies` (a thread), an edit is refused at Send with 409 if the description changed since (75); the manual timer |

### Added for `embarch-chat`

The route table moved verbatim to [interfaces/chat-routes.md](interfaces/chat-routes.md): every route takes the desk's bearer token; additions only; `?desk=` takes a desk's id or its name. **Close-out** (83): the mailbox kinds `end` and `unfinished`, written only by the desk; `POST /items/{id}/finish`; and `close_out` on each card of `GET /view` and in `work_item` of `GET /sessions/{sid}`, `{outcome, blockers:[{repo,reason}]}` or null, which the Work tab reads for its Finish button, plus `removal: {state, why}` (84). Every `GET /mailbox?folder=` is also the desk's sign that a window shows that folder.

**The caller's desk** (77). The desk's client (MCP server, hook, CLI) sends `x-embarch-session: <CLAUDE_CODE_SESSION_ID>` and `x-embarch-cwd: <its folder>` on every call when it runs inside a Claude Code session; `embarch-api` sends both on `GET /desks`. `/linear/mine`, `/linear/open`, `/linear/search`, `/pickup`, a new issue's default team and Project on `/drafts` (a `session_id` in the body stands in for the header) and `GET /desks`' `session` follow that session's desk: its folder's, else its work item's, else none, which is unscoped. A call with no session header works on the UI's desk. **`desks.json`** beside the state holds `{"desks": [...]}`, every desk, rewritten on start and on every desk saved or deleted; the old `open-desk.json` is deleted on start.

## The plugin

**The plugin** (`plugin/` in the repo, listed in the suite's `embarch` marketplace in `embarch-umbrella`, `embarch-promptu` decision 20): hooks on SessionStart, UserPromptSubmit, PostToolUse, Notification, Stop and SessionEnd, all running `embarch-desk hook`; a `desk` skill; and an MCP server `embarch-desk mcp` that is **agents' one access point to Linear and Harvest** ([decision 29](decisions.md)) — work items (`desk_whoami`, `desk_work_item`, `desk_set_work_item`, `desk_add_line`, `desk_remove_line` (85), `desk_list_items`, `desk_create_item`, `desk_link`, and `desk_add_repo` on a suite desk), Linear (`linear_get_issue` — newest 25 comments, `skip` reads older ones, 59, and its `files` list, `linear_get_file` — one image or file the issue lists, 81, `linear_my_issues`, `linear_search`, `linear_list_issues` — a team's issues in a named state, 79, `linear_teams` — each account's label and its teams, never a token, `github_pr_threads` — a PR's inline review threads root-then-replies, its review bodies with their state and `awaiting_author` on a thread the PR's author has not answered, complete past 100 comments, from `POST /github/pr-threads` (repo and number, or the session's item's open PR; `awaiting_only`; EMB-176), `linear_set_status`, `linear_draft_comment`, `linear_draft_issue`, `linear_draft_edit` — 75, `github_draft_review_replies` — replies to two or more review threads on one PR as one draft, `POST /drafts` kind `github_replies` with `repo`, `pr` and `gh_replies` of (`comment_id`, `body`), waiting for Send like the Linear drafts; Send checks every id is a review comment on the PR before posting any, and a mismatch stops the whole send; each body is posted under its thread's root and every URL is kept on the draft and returned as `urls`; a reply that fails leaves the draft open with the posted URLs kept, so the next Send posts only the rest; EMB-173), Harvest read-only (`harvest_entries`, `harvest_projects`) the manual timer (`desk_timer_start`, `desk_timer_stop`), restack tools (EMB-142), local git in the session's repo or worktree, never pushing, no desk route: `desk_restack` (`branch`, `base` as a ref, optional `old_base` for a rewritten base, `repo`) rebases the branch onto the base's tip and answers `rebased` or `conflict` with every hunk (file, hunk number, start and end line, both sides' text); `desk_restack_resolve` (`file`, `hunk` or the whole file, `choice` ours = the base's side, theirs = the branch's own change, neither) rewrites the block without markers; `desk_restack_continue` shows the conflicted files' diff against the base, and with `confirm` stages them and continues, refused while a marker line remains in any tracked file; `desk_restack_abort`; and desks (`desk_list_desks`, naming the desk this session works on; `desk_add_desk_note`, a standing note on the session's desk, which every SessionStart in its repos then carries, 74). **A commit becomes a tile line** when a PostToolUse `Bash` command contains `git commit` and HEAD is new; **an `embarch-api` build, flash, bootload, reset or study call becomes bench activity** ([decision 22](decisions.md)).

**Notes** (48–55). A note is `{id, ts_ms, session_id, kind, text, source_path}`; kind `memory` is a captured memory file, one per `source_path`, its versions kept. `desk_work_item` returns the brief for the calling session's item, then the desk notes `GET /sessions/{sid}` gives (74), and the SessionStart brief names it as the way to everything about the item; `desk_add_line` takes a `kind`, and an `item` to note another work item (78). **Capture** (52): a PostToolUse `Write`, `Edit` or `MultiEdit` whose `file_path` is under `~/.claude/projects/*/memory/` and is not `MEMORY.md` files the file's text after the write on the session's item — held until the session has one, as lines are. **Import** (54): once, on the first start that has notes. **Harvest** (50): the polish reads that day's notes of every kind.

**Connectors and CLI** moved verbatim to [interfaces/cli.md](interfaces/cli.md): the three connector kinds, the subcommands and `get`.
