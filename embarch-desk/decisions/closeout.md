# embarch-desk decisions: Done or Canceled closes an issue out

**Status:** active, 2026-11-10. Decision 83 split out of [sessions.md](sessions.md) on 2026-11-10, verbatim, when that file reached its reserve line (`tasks/desk/026`); 84 was written beside it.

What the desk does when an issue goes Done or Canceled: tell its window to end its chat (83), then remove its folder once no window shows it (84).

Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 83 — Done or Canceled tells the issue's window to end its chat; the folder is removed later, not here
**An issue's folder lived until the owner removed it by hand** (EMB-73: a landing that deleted it under a live chat left the chat unreachable on resume). The issue's status now ends it, in two halves: this one, the desk noticing and telling the window; and the removal (`tasks/desk/026`), which runs the same checks again. **Nothing closes in front of the owner without a click**: the window gets a message and a button.
- **Triggers.** `POST /linear/status` at once (the Work tab's menu and a chat's `linear_set_status` both go through it), and a move made in Linear itself when the reference index's refresh sees it (56, at most five minutes). **Done and Canceled are Linear's `completed` and `canceled` state types**, whatever a team names its states. The index's `RefIssue` gained `state_type` for it (GraphQL reads it; the MCP connector gives none, so a pass reads the issue again when the index's state name differs from the card's). A desk-made move also patches the index's row until the next refresh, so a stale fetch is not read as the issue moving back.
- **Only an issue with a `.dev-worktrees/<key>/` folder** (70) whose window folder (the card's `repo_path`) is inside it. A Start work worktree made outside a suite is untouched.
- **The checks** (`closeout::check`, one function), for every worktree in the folder (a symlink to a main clone is not one): no uncommitted files, untracked included; and for Done only, the worktree's branch is an ancestor of `origin/main` after `git fetch origin`. A canceled issue's work need not have landed. Each failure is one blocker, `{repo, reason}`: the repo's folder name and a one-line reason. A squash-merged branch is "not on origin/main" and blocks. [chosen]
- **Once per move.** The item records `close_out: {outcome, blockers}`; a pass that sees the same outcome posts nothing, a different one (Done then Canceled) runs again, and an open state clears the record, so the next move posts again. **The answer for the item carries it**: `close_out` on each card in `GET /view` and in `work_item` of `GET /sessions/{sid}`, null when none. The Work tab (outside the fleet's repos) reads it for its Finish button.
- **The contract with the chat**. Two mailbox kinds, **written only by the desk**; `POST /mailbox` refuses both, as it refuses `start` (46). `end`: `{kind, id, folder, item_id, issue_key, outcome}`, `outcome` `done` or `canceled`: every check passed, the window on `folder` ends the issue's chat. `unfinished`: the same plus `blockers`: nothing closes. Neither expires on the 10-minute launch clock: an entry waits until a window takes it or its folder is gone (a taken one is kept one claim's time, so a second take is told), and a newer one for a folder replaces an untaken older one. `POST /items/{id}/finish` re-runs the checks, posts a fresh entry and answers `{"ended":true}` or `{"ended":false,"blockers":[…]}`; 409 for an issue not Done or Canceled or with no folder here. The chat acts on the entry, not the answer. A window shows a folder while it polls `GET /mailbox?folder=`; polls stopping read as the window gone (`tasks/desk/026`). **Unverified:** the chat's side, which lands in parallel and does nothing new against a desk that predates it, and the `completed`/`canceled` types arriving over the MCP connector.

### 84 — The folder is removed once no window shows it
**83's second half** (`tasks/desk/026`, EMB-73): landing kept the folder, so nothing removed it. A separate decision beside 83, not an extension of it: 83 is the contract with the chat and stays whole; this one is the desk's own act, and it reuses 83's `closeout::check` and record.
- **A window shows a folder while it polls `GET /mailbox?folder=` for it.** The desk keeps the last poll per folder (in memory). A folder has no window once no poll for it, or for any folder inside it, has come for **180 s**, three of the chat's 60 s back-off. [chosen] The three triggers (the Close window button, the window closed any other way, no window open when the status moved) are all polls stopping, so there is one mechanism: the pass that runs every 30 s with the reference index.
- **A restart is not a window closing.** Absence is measured from the later of the last poll and the desk's own start, so a desk that has just started waits a full grace before it reads any folder as windowless.
- **Only when the desk can see windows.** With `settings.chat_panel` off a window may never poll: nothing is removed and the record says so. The setting read when the pass runs counts, so turning it off after a close-out also leaves the folder.
- **The checks run again immediately before removing** (the chat may have worked since 83 posted its `end`). A failure posts an `unfinished` naming each blocker and removes nothing.
- **Removal**, planned for every worktree before anything changes: for Canceled, each branch deleted on `origin` first (a remote without it is not an error, `git ls-remote` says), so a network failure leaves the folder whole; then per worktree `git worktree remove` from its main clone and `git branch -D`; then the folder with `remove_dir_all`, which **does not follow symlinks** (the sibling links `src/suite.rs` makes go, their targets stay). Never removed: a branch named `main` or `master`, a folder that is a symlink, a worktree whose `.git` is a directory (a clone). Any of these, or a git failure, is `left`, with the reason. A Done branch is deleted locally only: its work is on `origin/main`, and the remote's copy is the owner's to keep or prune.
- **The record says what happened.** `close_out.removal` is `{state, why}`: `waiting` (for the window), `removed`, or `left` (for the owner: checks failed, the setting is off, or a removal step failed). Finish re-runs the checks and, when they pass, waits again.
- **Not built:** removing a folder whose chat is open but not polling (a closed laptop reads as a closed window; the checks still hold, so nothing unlanded or uncommitted goes), and a squash-merged Done branch, which 83's check already blocks. **Unverified:** that the chat polls while its window is open and idle, and its back-off never exceeding 60 s (the chat's side, `tasks/chat/023`).
