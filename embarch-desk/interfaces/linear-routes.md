# embarch-desk: Linear and Promptu routes

**Status:** active, 2026-11-27 (`tasks/desk/049`). Split out of [../interfaces.md](../interfaces.md) when that file reached reserve — four route-table rows moved verbatim, not cut. Index and the bearer/port contract: [../interfaces.md](../interfaces.md); every route here takes the desk's bearer token except where a row says otherwise.

| Route | What |
|---|---|
| `GET /linear/issue/{key}?skip=N` (the newest 25 comments after skipping N, oldest first, with `comments_total`, `comments_truncated` and a `comments_note`; 59; and `files`, each `{url, title, found}`: the upload links and attachment records the issue lists; 81), `/linear/mine`; `POST /linear/issue/{key}/file` (`{url}` → `{kind: image, mime, data (base64), name, size}`, `{kind: text, text, name, size}` or `{kind: file, path, mime, name, size}`; a URL the issue does not list is a 400 naming the issue, a file over 10 MiB a refusal naming its size; 81); `POST /linear/search`, `/linear/status`, `POST /linear/issue/{key}/archive` (`{}` → `{key, archived: true}`: archives the issue, which still reads by key; HTTP only, no MCP tool; an MCP-connected workspace is refused, as Linear's MCP server has no archive; for `fleet-linear.py archive-done`, since Linear's free plan caps unarchived issues), `/linear/issues` (`{team, state, project?}` → `{workspace, team, state, project, issues, truncated, note?}`: a team's issues in a state by name, in the workspace the caller's desk follows (any on no desk; a team outside it is a 400 naming it, 79), capped at 500; an unknown team or state is a 400 listing the ones there are; 79); `POST /harvest/entries` | What the agent tools call; a key no workspace has is a 404 naming the desk that holds its team and that desk's folder, or saying no connected workspace has the team (77); `/linear/mine` and `/harvest/entries` carry `truncated` when their cap cut the read (59) |
| `POST /linear/issue/{key}/blocked-by` `{by: [keys]}` | Records that each issue of `by` blocks `key`, straight through like a status move, skipping one already recorded, and answers `key`'s `blocked_by`. `GET /linear/issue/{key}` carries `blocked_by` too, each `{key, state, state_type}`, read from a token workspace only; the fleet holds a blocked issue in Fleet Ready until every blocker is Done (owner, 2026-11-20) |
| `GET /linear/open`, `/linear/issue/{key}/states` | Every open issue in scope, assigned or not, with `truncated` as on `/linear/mine`; the states of an issue's team, by key, with no card needed (71). Issue rows from `/linear/mine`, `/linear/open`, `/linear/search` and `/pickup` name their `project`. `/linear/mine`, `/linear/open`, `/linear/search` and `/pickup` carry `scope`: the project filtered on, else `team <KEY>` for a team-bound desk, so an empty answer reads as nothing in that scope (34); a key reads from any connected workspace |
| `GET /promptu`; `GET /promptu/sheet`; `POST /promptu/sheet/{week}/{line}`; `POST /promptu/feel/{week}`; `POST /promptu/apply/{week}` | The Desk tab's Promptu section (65): each runs the `promptu` CLI and passes its JSON on, holding no Promptu logic. `/promptu` is `promptu desk --json`, cached 60 s, `{"promptu":1,"open":0}` when Promptu is absent or fails; `/promptu/sheet` is `week show --json` (`?week=` for another); the mark takes `{verdict: approve|cut, note?}` and runs `week mark`; the feel takes `{feel: better|same|worse}` (else a 400 before the binary runs) and runs `week mark --feel`, which takes no line id; apply runs `week apply` and answers each line's result, also when one failed. Without the binary the four others are a 503 naming it; a refusal (unknown line, settled sheet) is a 400 in Promptu's words. **HTTP only: no MCP tool reaches them**, an agent never marks or applies a sheet |
