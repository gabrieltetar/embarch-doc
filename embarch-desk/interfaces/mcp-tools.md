## The agent tools

The tools of `embarch-desk mcp`, agents' one access point to Linear and Harvest ([decision 29](../decisions.md)):

work items (`desk_whoami`, `desk_work_item`, `desk_set_work_item`, `desk_add_line`, `desk_remove_line` (85), `desk_list_items`, `desk_create_item`, `desk_link`, and `desk_add_repo` on a suite desk), Linear (`linear_get_issue` — newest 25 comments, `skip` reads older ones, 59, and its `files` list, `linear_get_file` — one image or file the issue lists, 81, `linear_my_issues`, `linear_search`, `linear_list_issues` — a team's issues in a named state, 79, `linear_teams` — each account's label and its teams, never a token, `github_pr_threads` — a PR's inline review threads root-then-replies, its review bodies with their state and `awaiting_author` on a thread the PR's author has not answered, complete past 100 comments, from `POST /github/pr-threads` (repo and number, or the session's item's open PR; `awaiting_only`; EMB-176), `linear_set_status`, `linear_draft_comment`, `linear_draft_issue`, `linear_draft_edit` — 75, `github_draft_review_replies` — replies to two or more review threads on one PR as one draft, `POST /drafts` kind `github_replies` with `repo`, `pr` and `gh_replies` of (`comment_id`, `body`), waiting for Send like the Linear drafts; Send checks every id is a review comment on the PR before posting any, and a mismatch stops the whole send; each body is posted under its thread's root and every URL is kept on the draft and returned as `urls`; a reply that fails leaves the draft open with the posted URLs kept, so the next Send posts only the rest; EMB-173, 89), Harvest read-only (`harvest_entries`, `harvest_projects`) the manual timer (`desk_timer_start`, `desk_timer_stop`), restack tools (EMB-142, 90), local git in the session's repo or worktree, never pushing, no desk route: `desk_restack` (`branch`, `base` as a ref, optional `old_base` for a rewritten base, `repo`) rebases the branch onto the base's tip and answers `rebased` or `conflict` with every hunk (file, hunk number, start and end line, both sides' text); `desk_restack_resolve` (`file`, `hunk` or the whole file, `choice` ours = the base's side, theirs = the branch's own change, neither) rewrites the block without markers; `desk_restack_continue` shows the conflicted files' diff against the base, and with `confirm` stages them and continues, refused while a marker line remains in any tracked file; `desk_restack_abort`; and desks (`desk_list_desks`, naming the desk this session works on; `desk_add_desk_note`, a standing note on the session's desk, which every SessionStart in its repos then carries, 74).

**Draft revision** (EMB-165, 88, `POST /drafts/{id}/revise`, `GET /drafts/{id}`): `desk_revise_draft` (`draft_id`, `section` or none to append, or for a `github_replies` draft `comment_id` to replace that one reply; `text`) changes a draft still waiting on the Desk tab without disturbing the owner's edits, refused with what collided when the owner changed that section or reply (a posted reply is refused too, EMB-212); `desk_get_draft` (`draft_id`, optional `from_version`, `to_version`) answers the draft in any state with the agent's last version and `owner_diff`, so after a Send the owner's edits alone are what to learn from, plus `versions` (every agent revision and owner edit, EMB-211); naming either version number adds `version_diff` between those two.
