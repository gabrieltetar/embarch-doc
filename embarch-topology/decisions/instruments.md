### 49 — A bench instrument is declared with its port identity and its line facts, in its own table

**`Instrument { name, protocol: scpi, port: UsbPortId, baud, write_terminator, read_terminator, min_interval_ms, ack_ok?, ack_err? }`**, an `instruments` table in `enrollment.toml` beside `bootload_ports` (decision 36), skipped when empty so a store that never declared one is rewritten unchanged. It is found by `UsbPortId` exactly as a bootload port is, and an identity matching more than one live port is an error naming every one, never a pick.

**Declared, never detected**, for decision 36's reason made sharper: the first instrument sits behind a CH340 bridge, whose VID:PID every CH340 shares and which carries no USB serial number. **Two instruments one live port could match both of are refused at declaration**, as a bootload pair is; the remedy is a serial number or an interface that differs, and saying so at declaration puts it in front of the person who can act on it.

**The line facts are the instrument's, so they are declared once here and every caller reads them.** The first instrument taught them the hard way: it ignores a command ended by CR alone, ends replies with CR LF, wants 200 ms between commands, answers a set `Rexecu success` or `Rexecu err` and an unknown command `Rcmd err`, and a partial line poisons its parser for the next command. Carried in each caller, a study step and a one-off exchange would disagree about them on the first edit. So: terminators default to LF out and CR LF back; `min_interval_ms` defaults to 0; **`ack_ok` is what makes a set checkable**, and `ack_err` without `ack_ok` is refused because a set is judged by `ack_ok` alone (decision 104 has why an answer holding neither is a failure).

**The wire types live here too**: `InstrumentExchange` (one command: `line`, `query`, `timeout_ms`, `port_wait_ms`), `InstrumentReply` (the raw reply line, `terminated`, `ack`, the flush line's answer, pacing and timing), and `Ack` (`ok`, `refused`, `unacknowledged`), so Core and `embarch-core-client` cannot drift (decision 31's posture). `judge_ack` and `InstrumentReply::succeeded` say what an answer means in one place. **Nothing parses a value**: a reply is text, an instrument's own prefix kept.

**A safe-off is declared beside the line facts, on both halves of a bench** (amended 2026-11-24, `tasks/topology/072`). `Instrument.safe_off` is the lines sent in order, with the instrument's own terminators and pacing, to switch its output off; `SignalLink.safe_off: Option<String>` is the one shell line sent to the bench board that signal leaves (decision 48's origin) to switch its outputs off. They exist so Core's safe-off, at a graceful stop and at start, builds its command from the declaration, never from a step's text. Both are optional, omitted when empty (a store written before them loads and is rewritten byte for byte), and a declaration with none is not refused: Core lists it as "no safe-off declared". Each line is checked like an exchange's `line`: not empty, no CR or LF, at most 4096 bytes (`MAX_SAFE_OFF_LINE_LEN`, Core's `MAX_WRITE_BYTES` repeated because this crate cannot depend on Core, assumed equal). Declared like any other field: the person's act on an attested Core, the agent's and labelled so on an unattested one. Using the field is Core's work, not this crate's.

**A name is a URL path segment**: ASCII letters, digits, `-`, `_`, `.`, at most 64 bytes. Only `scpi` exists; `protocol` is an enum so a second one is a new variant, not a reinterpretation.

**What an instrument's reading is worth is declared beside it: decision 51** (2026-11-25).

**Not verified:** no instrument has been declared on a real bench. The line facts above are the field's (seen on the unit or in its manual, recorded in `tasks/suite/049`), not a run of this code. One of them matters to a reader of an error: the CH340 enumerates with the load switched off, so a query with no reply is not a missing port.

### 51 — An instrument declares what its reading is worth: metrology and calibration

**`Instrument.metrology: [Metrology]`**, one entry per quantity it measures, `{quantity, unit, resolution, U, k, basis, range: {min, max}}`, and **`Instrument.calibration: Calibration?`**, `{serial, certificate_ref, due: yyyy-mm-dd, certificate_sha256?}` (`tasks/suite/063`, EMB-358). The HIL design has each source declare its resolution and `U` with its coverage factor and basis, an instrument's being the person's act, and checks a calibration's due date against every measurement it made ([03](../../notes/hil/03-test.md), "The verdict"; [06](../../notes/hil/06-report-and-publish.md), "The audit appendix"). Both are optional, omitted when empty, so a store written before them loads and is rewritten byte for byte; a declaration with neither is not refused, since the report prints "calibration undeclared" rather than the store refusing it.

**`check` refuses, naming the field**: a negative or non-finite `resolution` or `U`; a `k` not above zero; a `range` whose `min` is not below its `max`; an empty `quantity` or `unit`; an empty `serial` or `certificate_ref`; a `due` that is not a real date written `yyyy-mm-dd`; a `certificate_sha256` that is not 64 lower-case hex digits. **`U` keeps its capital on the wire**, as `embarch-study-designer`'s `ObservedNumber` does. **`basis` is an enum**, `datasheet`, `certificate` or `declared`, so the report's label is a closed set. **`k` is required**, where a person's observed number defaults it to 2: a datasheet or certificate states its own, and an instrument's declaration is the root a guard band rests on. Two entries for one quantity are not refused; which applies to a measurement is Core's, when it stamps them (EMB-360).

**Nothing reads them yet.** Core's `PUT /instruments` accepts and checks them through this type; `embarch-api`'s `declare_instrument` and `embarch-ui`'s Make live build an `Instrument` with neither, so **a re-declaration through either writes none, and replaces a stored one** — passing and keeping them is EMB-375's. **Rejected for now: metrology in Core's own store**, with no topology change (plan choice 14, the owner's to strike): the declaration is one row read by Core, the API and the UI, and a second store for its numbers is two places for one instrument.
