### 22 — Both toolchain-free test legs run above `run-all.sh`'s `WEST` guard

`tests/run-all.sh`'s guard — `WEST="${WEST:?...}"` — used to sit **between** the two host-Python legs: `decoder_unit.py` above it, `cross_decoder.py` below. Nothing about the ordering was load-bearing; it was an accident of the file's history, and its cost was total rather than partial. `cross_decoder.py` needs neither `west` nor `ZEPHYR_BASE` — its own comment says so — but a script under `set -euo pipefail` aborts at its first unset variable, so a bare checkout with no `WEST` never reached it at all. `README.md` claimed *"only the three Zephyr legs need a toolchain,"* which was false on this file's own ordering: a fourth, toolchain-free leg was gated behind the same guard as the three that actually need one. **Both host-Python legs now run first**, and the guard moved below both. Decision 23 covers what `cross_decoder.py` does once it can actually run in that position: a missing sibling-repo fixture is a skip, not a failure, and that skip has to survive to the exit summary.

### 23 — A skipped cross-decoder is a skip, not a failure, and is restated in the final summary rather than left in mid-stream output

**A missing sibling-repo fixture stays a skip, not a failure.** `cross_decoder.py` reaches into `embarch-core/tests/fixtures/` and `embarch-ui/tests/fixtures/` for committed bytes two other repos own; decision 4 in `decisions/layout.md` is why the check exists at all — *"a wire change is not done ... until every host that decodes it has been re-measured against it"* — but decision 4 is about a wire change inside **this** repo, not about what a clone of this repo alone is entitled to assume exists beside it. `DOC-PROTOCOL.md` §2's sibling layout is a convention for a machine running the whole suite, not a property of `embarch-outpost` on its own — a solo clone, a fork, or a CI runner checking out this repo alone has every right not to have `embarch-core` or `embarch-ui` beside it, and failing a repo's own test suite over another repo's absence would make `embarch-outpost` not standalone. So the check does the next best thing: it runs whenever it can, and it says loudly, in two places rather than one, when it could not. That is the fix in the other half of this decision:

**A skip that is real still has to survive to the exit summary.** `cross_decoder.py` prints `SKIP: ...` and returns 0 the moment it runs, which is necessary for it to stay a skip and not an abort, but sufficient to let a skipped run look identical to a green one in a scrollback nobody reads to the top. `run-all.sh` now greps its output for the `SKIP:` line and restates it at the end of the run — so a run that checked nothing against the two sibling repos says so at the bottom, where a reader who only checked the exit code would otherwise never see it. **The note is printed from the `EXIT` trap and not only from the summary block, and that distinction is the whole fix on the one path decision 22 is about**: a bare checkout with no `WEST` runs both host legs and then stops at the guard, forty lines above the summary, so a summary-only note would have been unreachable in exactly the configuration that motivated moving the guard in decision 22. Verified both ways with `WEST` and `ZEPHYR_BASE` unset [2026-09-07]: with the sibling repos present the cross-decoder ran for real — *"PASS: both decoders agree on all 831 rows of 41 frames"* — and printed no note; with them absent it printed `SKIP:` mid-stream and the note after the guard's abort. This does not change what counts as failure: a real disagreement between decoders still prints `FAIL:` and returns 1, which still aborts the script under `pipefail`, unchanged by this decision.

*Rejected: fail the leg when the fixtures are missing.* Considered, because a silent skip is the shape of bug this whole suite exists to distrust. Declined because the absent fixtures are not this repo's defect to fail on — they belong to two other repos' test trees, and a repo cannot assert its own tests are green or red over a fact only a sibling checkout controls. The remaining risk — a real drift going unnoticed because nobody ever runs this leg with the siblings present — is priced by making the skip loud rather than by making absence fatal. Closing it for real would mean guaranteeing the siblings are actually there when it matters, which is what a CI workflow would buy; this repo has never had one (`../../embarch.md` §5), and whether to build one is a suite-scope call this repo cannot file (`../../../embarch-fleet/protocol.md` §8), not a problem parked against any task on disk.
