- 2026-08-26 — **The `.eap` mechanism becomes runnable: `StudyStart` carries a manifest, and dev-bench executes it.** Decisions 58-62 shipped every `.eap` type, seal and action and stopped **one field short of the wire** — `DevBenchMessage::StudyStart` had no `protocols`, so `Action::RunProtocol` named an index into something dev-bench had never been sent ([embarch-decision-reversals.md](../embarch-decision-reversals.md) row 68). `protocols`/`protocols_crc` are appended after `dev_bench_log_level`; decision 58 is amended and §4.9 restated. Schema stays **v15 wire / v17 host** — the intermediate shape was never built into a firmware or deployed anywhere, so extending v15 inside the same design pass is the honest record and spending v16 on a state that only ever existed in one file is not (`schema_version.rs` now carries both entries, which the bump itself had not written).

    `embarch-core` gains the **third pre-flight check**: `protocols_crc` recomputed and named independently of the other two, `validate_protocol` *called* rather than reimplemented (the posture `validate_taps` already set), and both of a `RunProtocol` step's indices range-checked — the two `validate_protocol` structurally cannot see, because they live on a `Step` rather than inside a manifest. §7's two `.eap` bullets close: the interpreter exists ([embarch-dev-bench/design.md](../embarch-dev-bench/design.md) §3 decision 41), and the unmeasured bounds are measured. **Both halves of that estimate were wrong in opposite directions** — the real C `ProtocolDef` is 4,376 bytes against the 17,496 this doc sized against, and the dominant cost turned out to be the *wire* bound rather than the storage.

    231 → 232 tests here (a `StudyStart`-carrying-a-protocol wire vector and a populated `StepResult.protocol` one), `embarch-core` 152 → 158, `embarch-dev-bench` 42 → 57 ztest cases, `clippy --all-features --all-targets -D warnings` clean everywhere. **Still not run against a real DUT**: what exists is a bench that can execute a manifest, and no engineer has authored one yet (§7).
- 2026-08-26 — **New decisions 58–62: an engineer can finally tell this suite how a DUT's protocol works, and dev-bench runs it.** Closes the write direction §3 decision 39 rejected as premature and gives [milestone-11.md](milestone-11.md) §3.8 the mechanism it has been blocked on since 2026-08-24. `embarch/protocols/*.eap` is a small purpose-built grammar, **resolved into `Study.protocols` at build time** and sealed by a third CRC — not referenced by a manifest CRC, which is what the design draft proposed and what [embarch-decision-reversals.md](../embarch-decision-reversals.md) row 37 had reversed the day before. `Action::RunProtocol { protocol, entry_state }`, `ProtocolOutcome`, and a fixed primitive set **split** so that only what a guard can reach crosses the wire. Schema **v14 → v15 wire, v16 → v17 host**; `StepResult.protocol` appended last so the pinned `WIRE_STEP_RESULT` diff is one byte, and `embarch-dev-bench`'s C is owed a re-pin (§3 decision 36).

    **Four things the draft asked for are not built, each because a decision made within the previous eight days already answered it, and all four are recorded in the decisions rather than quietly dropped**: the manifest CRC (decision 52 — Core cannot read the firmware repo); `ProtocolOutcome.decoded_fields` (decision 54 — a bounded copy of unbounded streamed data); reaching `Study.validations` (decision 48 — the field does not exist); and `StreamEncoding::GattDecoded` (decision 52 shipped the rendering one day earlier, so an `.eap` frame lowers into its `StructLayout` instead). Two arguments *against* dev-bench-side execution were made during the design pass and both were wrong — a stale 98.5% SRAM figure and an overstated serial-latency cost — and decision 60 records the corrections, because they are what actually decided it.

    **Implemented the same day**, 231 tests green (`embarch-study-designer` 211 lib + 12 worked-protocol + 8 firmware-vector), `clippy --all-features --all-targets -D warnings` clean, every feature combination building, and the `no_std` staticlib still cross-compiling for `thumbv8m.main-none-eabi`. `embarch-core` (152), `embarch-api` (55) and `embarch-ui` (65) all green after picking up the two new `Study` fields. **Not run on hardware and not runnable yet** — the real-time interpreter is `embarch-dev-bench`'s own scope and does not exist, so the only thing that has ever executed a `.eap` file is the host-side reference interpreter in this crate (§7).

    One finding came from writing the worked examples as tests rather than as prose, which is why they are tests: an `on_event` arm with no `otherwise` stays in its state **without re-entering**, so the first draft of the BDS fixture consumed every chunk correctly, acked none of them, and stalled at its own watchdog. `otherwise: goto <itself>` is the self-transition a pump loop needs. Both behaviors are real; the author says which (§3 decision 60).
