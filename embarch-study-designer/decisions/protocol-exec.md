# embarch-study-designer decisions: Executing a protocol

**Status:** active, 2026-09-02.

What a `RunProtocol` step does on the bench, and what a run may report.

Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 60 — `Action::RunProtocol` — stateful sequencing, executed by dev-bench

It hands the link to a declared state machine for the length of one step: named states, entry writes, event transitions with `remember`/`when`/`otherwise`, timeout retries, and terminal states mapping to the existing outcome. **It spans steps the way the monitor-window pair does, but where that opens a time window this runs a machine** — which is what decision 39's rejected send-and-expect pair was reaching for and could not express.

**Where the loop closes was the hard question, and the first answer was wrong.** The draft asserted both that this crosses the wire like every other action *and* that the interpreter is host-side. **Those are incompatible: something has to close decode → decide → write.** Two arguments for Core closing it were made and **both were mistaken, recorded because the correction is the reasoning:** that the board was at 98.5% of its RAM segment — **real but stale**, since retiring one field took it to 81% and another 10.5 KB was a mis-sized buffer — and that Core in the loop is too slow, when **a round trip is single-digit milliseconds against a BLE connection interval of 7.5–30 ms that already dominates, against a stall watchdog measured in seconds.**

**What actually decides it is the third consideration: under Core-side execution nothing new crosses the wire, but Core would have to send something mid-study for the first time**, and under bench-side execution the manifest crosses while the lifecycle does not change. Bench-side keeps the firmware's receive-then-run model and Core's silence after dispatch exactly as they are. **The cost is stated rather than hidden:** what a payload *means* now reaches the bench, **which is the knowledge decision 39 took away from it.** Decision 59's split keeps that to the smallest set of primitives a machine can reach, and **the mid-study write tier stays unbuilt, which is the compensating simplification.**

**Nothing here can transition on a write's own ATT response, and that is deliberate.** On the DUT this was designed against, **a control-point write's response confirms only that the write was *accepted*; the authoritative answer arrives later as an independent notification on a different characteristic.** A machine that could branch on the ack **would be branching on the wrong fact and would look correct doing it.**

**The expression evaluator is a small fixed set, and the architecture made it smaller than the draft's:** integer literals, a run's own carried state, a scalar of the frame that triggered the event, `len()` of a byte span, saturating `+`, and one comparison per guard.

Each omission has a stated reason. **Byte-span concatenation** would have accumulated an entire download in a session variable to compare its length against a total — **and on the bench there is nowhere to put those bytes and nowhere they are needed**, since the chunks already stream out on their own tap as they arrive, so a running byte count says the same thing in eight bytes of state. **Session variables are therefore integers only.** The other arithmetic operators: **no worked protocol needs one, and each is a permanent widening.** Boolean operators: **`a && b` is two states and `!a` is swapping `when` and `otherwise`.** Nesting, parentheses, and any function but `len()`: an expression is one level, **checkable at a glance.**

**Addition saturates rather than wrapping**, because a wrapping counter is **a plausible wrong number, the failure this crate keeps refusing**, and a saturated one stops a guard passing, which the step timeout catches and reports. An operand that cannot resolve — a field a truncated notification did not carry — **makes a guard false, never true, and makes a write not happen rather than happen with a zero substituted in.**

**One finding came out of writing the tests rather than the design.** An event arm with no `otherwise` **consumes the frame and stays in the state *without re-entering it*** — no entry re-send, timeout still running from the original entry. **A self-transition is a different thing: it re-enters, re-sends the flow-control ack, and restarts the stall watchdog.** A pump loop needs the second and the first draft wrote the first: **it consumed every chunk correctly, acked none of them, and stalled at the watchdog.** Both behaviours are real and the author says which.

### 62 — A protocol run reports the state it stopped in, and nothing it could lie about

Decoded fields are addressable by name everywhere inside a manifest — in guards, in `remember`, in a write — **which is what makes the state machine expressible at all.** The reported outcome is **the final state and the verdict, and nothing more.**

**Two things the draft wanted are not built, both answered by a decision made days earlier.** It had the step result carrying a bounded vector of every decoded field a run saw — **the exact shape decision 54 retired the GATT-activity field for, on measurement: a bounded in-memory copy of something unbounded and streamed lets a result *look* complete while holding a fraction of what arrived.** Decoded values reach a reader the way every other captured byte does, through the declared tap. **Whether the final state was terminal is not stored either — it is a lookup in the definition the study already carries, and a stored copy could disagree with it.** And it had decoded output reaching post-hoc validation, **which does not exist**: decision 48 removed it outright, and **a manifest's terminal states are the assertion instead** — declared where the protocol knowledge lives.

**Where the outcome lands, confirmed rather than assumed.** Core hand-writes only the result file's *envelope* and serializes each step result through serde, **so this field reaches the file automatically and a test asserts it does** — and with it the study endpoint and the per-step event. **The stream index deliberately says nothing about it:** that file describes declared capture channels, **and a protocol run is not one.**

**A decoded-GATT stream encoding is not added either.** The draft proposed it mirroring a precedent **that no longer exists** (decision 58), and it would have been a second rendering path one day after decision 52 shipped the first. Instead **a frame flat enough to be one lowers into decision 52's own layout**, so a frame an engineer already described for a state machine **does not have to be described again to also be rendered. One rendering mechanism, two front ends.** A frame the layout cannot express gets **no layout rather than an approximate one** — decision 52's own rule, because **the raw bytes are on disk either way, so a missing rendering can be redone and a wrong one silently misreads every row.**
