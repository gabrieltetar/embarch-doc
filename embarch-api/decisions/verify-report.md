# embarch-api decisions: `verify`'s checks 4, 6 and 9

**Status:** active, 2026-11-22 (`tasks/api/171`, HIL M1.11, second half).

Decisions 122 to 125. Index: [../decisions.md](../decisions.md). Surface: [../interfaces/publish.md](../interfaces/publish.md#verify). Source: `notes/hil/06-report-and-publish.md`, "Verify" checks 4, 6 and 9. The first half: [verify.md](verify.md).

### 122 - Check 9 is a whitelist over the parsed tree, and `publish` refuses by the same one

`src/report_whitelist.rs` parses `report.typ` with `typst::syntax` and walks the tree. It refuses: `eval`, `read`, `json`, `csv`, `yaml`, `toml`, `cbor`, `xml`, `plugin`, `bibliography` and `svg` as an identifier anywhere, and `include`; every import but `"@embarch/report:<version>"`, and from it any name the helper does not export or any renamed one; a helper call or `image` used as a value (an alias) or called inside a closure, show rule or set rule (a wrapper); a helper call whose file is not `path("<literal>")` of a file Core signs (`measurements.json`, `report-data.json`, `events.json`, `study.json`, `streams/*`), or whose `x`, `y` or `bins` is not a literal; `image()` of anything but a `streams/` literal; a `footer` argument of `page`. It does **not** refuse a numeral computed from other code: check 4 reads what the PDF prints, which is the only place a computed numeral is visible. `verify` runs it on the zip's `report.typ` and `appendix.typ`, `publish` on the source before Core is asked; decisions 114 and 115's lexical refusals stay in front of it for their messages. The list of admitted names (`minmax-plot`, `m`, `plot-ticks`, `image`) is this crate's, beside the helper package it must track.

### 123 - Check 4 admits a number by one of six rules, and the appendix's own numbers make it partial

Every number `numbers_in_word` finds in the extracted words (after the opaque-word rule) must be: an axis tick `verify` derives with `plot_ticks` from the signed series of each `minmax-plot` the whitelist found (the helper's binning repeated, text equality); a signed measurement at the digits written (the oracle's `same_at`, mV and V alike); equal to a numeric value in `report-data.json` or `events.json`; a number the rescan of the prose files and `report.typ` lists; the footer's page number; or a number printed in `appendix.typ`'s string literals. `events.json`'s strings and numbers join `report-data.json`'s because the appendix prints the steps from it. The last rule is **partial, never pass**: `appendix.typ` is embarch-api's file, not Core's, so a number only it vouches for rests on embarch-api; the result lists them. A `cited, does not match` row of the rescan fails. **Measured on a Typst and lilaq PDF (first real test):** the extractor's word gap and 0.5 em fallback needed no change; the footer's baseline sits at 14.96 mm (11 pt) and just over 15 mm under the appendix's 9 pt, so this crate uses **8 to 16 mm**, which `hil-pdf.md`'s band now states (measured on one page there too). The page width is A4's, since the compile sets no paper; a Letter page is inside the 5 mm centre tolerance. Not measured: a font the embedded set lacks, a table cell wrapped across lines inside a number.

### 124 - Check 6 recomputes `report-data.json` independently, and Core's builder does not move

Every field is rebuilt from the signed record, `events.json`, the run log's segment and the signed manifest (revision and Core version from the manifest, the key id from the given key), the attestation's explanatory text excepted as Core's wording. `verify` does not call Core's builder and is not given it through the shared crate: a verifier that ran the function it checks would agree with it by construction, and the rule is a dozen lines of reading. The cost is two copies that can drift, caught by a published zip failing check 6 against a newer Core. The PDF is then held to print the run id, the status, the step-count line, the attestation label, who began and published the run, and the revision sentence, compared with whitespace removed so the extractor's word breaks do not matter. A verdict word or a count Core adds to `report-data.json` and the PDF prints is the same check's: the keys are compared whole, so a key `verify` does not know fails.

### 125 - Carried packages are hashed against this build's list, and missing ones fail

Every `typst-packages/` file in the zip is hashed against `vendored_files()`, the embedded copy of this checkout's packages (06: the installed release's list, or a source build's checkout). A file off the list, or differing, fails; so does a list file missing from a zip that carries any or whose `report.typ` imports the helper, since the PDF could not be rebuilt. A `report.typ` that is `publish`'s generated data section carries no packages and imports none.
