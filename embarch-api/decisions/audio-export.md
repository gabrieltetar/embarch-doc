### 130 - A framed analog tap exports as WAV from its raw block file, the study's declarations read from the Study JSON

`embarch_api::audio_export::run(core, request)` is the whole export; the MCP tool `export_audio` and `export-audio <study_id> --name --study-file [--out-dir]` only print. **Format (owner's decision 12):** 16-bit PCM mono at the tap's declared rate, `(code - mid-scale) * 2^(16 - bits)` so a 12-bit code is multiplied by 16, `bits` from the capture's start header; one `<study_id>-<tap>-segNN.wav` per gap-free segment, each with a `.txt` Audacity label file beside it (tab-separated start, end, label, seconds, a marker being a point) and the same markers as RIFF `cue ` points with `LIST`/`adtl`/`labl` texts, all written by hand (a few dozen lines; no small crate carries `cue `). A `<study_id>-<tap>-gaps.csv` and the outcome's `gaps` list where each segment ended, the indices either side and the samples missing.

- **The raw file is the input, so no Core route is added.** `GET /study/{id}/stream/{name}?raw=1` serves the framed tap whole (EMB-475); gaps are re-derived with the study-designer crate's `IndexTracker` and markers from each verified block's event word, the same reading Core's `events.csv` rows come from. **Rejected:** a Core route for `events.csv`, a second reading of the same bytes through a new surface.
- **The rate, layout and folder come from the Study JSON the run was submitted from** (`study_file`), because Core serves none of them back: the rate is `AnalogInput.sample_hz`, the layout the tap's `AnalogBlocks` check, the folder `session.export_dir`. A relative folder resolves against the study file's folder (Core resolves it on its own side; this crate has only the file); `--out-dir` replaces it. **Rejected:** taking the rate from the start header alone, which is what the bench reports and not what the study declared; a mismatch is a warning and the declared rate is used, as Core does.
- **A tap with no declared rate is refused with its reason**, before anything is fetched: only an `AnalogInput` source declares an audio rate (a power tap's `sample_hz` is not framed audio). Also refused, each saying what to change: no `AnalogBlocks` layout, more than one channel (which channel a mono file takes is not defined), no start header (resolution unknown), a resolution outside 1 to 15, no export folder, no verified block.
- **A segment ends at a gap or at an index that goes backwards or repeats.** A block that does not verify is skipped to the next magic and shows as a gap between its neighbours. A block names only its first marker edge's offset: further edges it counts are not placed and are a warning, never invented.
- **[Assumed]:** raw codes are unsigned counts of `bits` bits, mid-scale `2^(bits-1)`, held in an `i16` (so at most 15 bits). **Owed to the bench:** that `embarch-dev-bench` emits unsigned codes, and whether Audacity reads the `cue ` points and the label file as intended (checked here only by parsing the RIFF back).
- Existing files of the same name are overwritten: an export is a function of the capture.
