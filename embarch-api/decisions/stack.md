# embarch-api decisions: The review-fold and restack command family

**Status:** active, 2026-10-28.

Index: [../decisions.md](../decisions.md). Current truth: [../interfaces/stack.md](../interfaces/stack.md).

### 96 — `stack plan | fold | restack` replaces the hand-kept fold map and the broad git permission rules

`tasks/api/130`: 20 of 25 auto-mode denials hit rebase, cherry-pick, amend or force-push, and fixes piled up as additive commits behind a hand-kept map. **CLI only, host-side only**: `git` and nothing else, so `main` dispatches it before config or Core. Only `patches::parse_diff` ties it to this crate, so it may move to its own.

- **`plan`** diffs the working tree (and every commit above `--since`, default HEAD) against the reviewed point, attributes each hunk to the newest commit in `<base>..<since>` that last touched its old lines (`git blame`), and commits one `fixup! <sha>` per target. Fixups are built **without touching the working tree**: each target's hunks become a commit off the reviewed point, chained with `git merge-tree --write-tree`, then `reset --mixed` onto the chain. What no commit owns — new or untracked files, lines older than the base, deletions, renames, binaries — stays uncommitted in the tree and goes, hunk text and reason, to the **plan file** (default `<git dir>/embarch-stack-plan.md`), which replaces the hand-kept map. Commits above `--since` are replaced by the fixups, so the pre-plan tip is backed up first.
- **`fold`** backs up the checked-out branch and every branch pointing into the range, turns each curation line into an empty `amend!` commit (body kept), and runs `rebase -i --autosquash --update-refs` with a no-op sequence editor. **Tree identity is checked with git directly**, `<tip>^{tree}` before and after; a mismatch restores the backup. Never pushes.
- **`restack <bottom>..<top>`**: the stack is every local branch between the two, found by ancestry **or by a backup of the branch** that the top still contains (a folded branch is no longer an ancestor of the branches above it). Without `--onto`, the lowest branch not under its predecessor is rebased with `--update-refs --onto <new prev tip> <old prev tip> <top>`, the old tip being the predecessor's newest backup the branch still contains; repeated until the chain is linear. With `--onto <ref>` it is `rebase --update-refs <ref> <top>`, which drops commits already in `<ref>` by patch-id — a bottom PR landed by rebase merge. Branches whose commits are all in `<ref>` (`git cherry`) are reported `landed` and not pushed. Then one **`git push --atomic`** with a `--force-with-lease=<branch>:<sha>` per branch, the sha being the remote-tracking ref this checkout last saw (empty, "must not exist", when there is none): a ref moved by another session rejects the whole push and the stack stays restacked locally.
- **Backups live at `refs/backup/<branch>-<12 sha>`, not under `refs/heads`**, where the first build's were moved by `rebase --update-refs` with every other branch pointing into the range — a backup that follows the rewrite is not one. Listing: `git for-each-ref refs/backup`.
- **Refused by name rather than guessed:** a merge commit in the range, a detached HEAD, a dirty tree (`fold`, `restack`).

**Measured** on throwaway repos only (`tests/stack_cli.rs`: a 3-commit plan with unplaceable hunks, `--since`, fold with curation and tree identity, the conflict path, a 4-branch stack on a local bare remote, the lease abort, the rebase-merged bottom); not yet on a real PR stack, a forge, or a remote that rewrites on merge differently from `cherry-pick`. git 2.38+ is **assumed** for `merge-tree --write-tree` (2.43 here). A hunk spanning two commits is attributed to the newest.

**Rejected:** `build --each --same-tree-as` as the identity proof (`tasks/api/127`: toolchain-gated, unbuilt, and a plain tree compare is exact); fixup commits made by `cherry-pick` on a live tree (a conflict leaves the engineer's work half applied); a plan-file format other than readable markdown.
