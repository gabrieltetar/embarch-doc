# embarch-api decisions: `publish`, the numeric oracle, authorship and revisions

**Status:** active, 2026-11-22 (`tasks/api/168`, HIL M1.10, second half).

Decisions 115 to 117 and 126. Index: [../decisions.md](../decisions.md). First half: [publish.md](publish.md) (112 to 114). Surface and layout: [../interfaces/publish.md](../interfaces/publish.md). Source: `notes/hil/02-study.md` ("The run's files are the numeric oracle"), `notes/hil/06-report-and-publish.md`.

### 115 - The oracle listing is a lexical scan of the sources, and a picture other than a signed capture is refused

`publish_oracle::rows` lists every number of each prose file and of `report.typ`, using the token grammar of `embarch-study-designer/interfaces/hil-pdf.md`, as **cited** (names a measurement, by `#m("name")` or `[name]` within two words after the number, and equals it at the significant digits written, in its unit or one a `mV`/`V`, `ms`/`s`, `mA`/`A`, `mW`/`W`, `Hz`/`kHz` pair converts), **cited, does not match**, **tagged** (`(derived)`, `(spec)`, `(inference)`, `(analysis)`), **unbound** (cites nothing, equals some measurement) or **untagged** (cites nothing, equals none, 02's "untagged number that matches no measurement"), and every numeric literal of `report.typ`'s code that is not a length, angle or ratio as **hardcoded**. A bare `#m("name")` is listed cited. A word byte-equal to a string `report-data.json` holds is opaque. **A listing never refuses a publish**; `verify` rescans. **The scan is lexical** (markup and code mode, strings, comments, brackets), not a Typst parse, and **errs toward listing**: `bins: 50` is hardcoded though it never reaches the page; `#set`, `#show` and `#import` are skipped. **[Assumed]:** two words is the reach of a citation, and a number in `$` math is a markup number. **Pictures:** `image(...)`, `svg(...)` or `image.<field>` in code is refused before Core is asked, **except `image()` of a `streams/` path**, the capture Core signs (02's exception, read as that path). The generated data section is not scanned (its numbers are table cells from signed data); operator notes are not prose. **Not measured:** a real study's report.typ.

### 116 - A prose block's author is Core's scope plus the caller's claim

`publish` takes prose blocks (`{name, text, author, reviewed_by}`; `--prose <path>`, `--prose-author`, `--prose-reviewed-by`), adopts each as `prose` named `prose/<name>` before `report-data`, and carries it in the zip as an embarch-api file. Core records the token's **scope** and the text's hash (`embarch-core` decision 117) and **no name or model id**, so the appendix's Author column is built from Core's `adopted` rows of that file and the caller's claim: all rows `agent` read `agent (<model id>)`; the first `agent` and the last not, `agent, reviewed by <name>`; otherwise the name. A missing claim prints "model id not given" or "name not given", and the table's note says the names are claims. **Not 02's whole rule:** that a block entered with an agent's token reads "agent" whatever name it carries is Core's scope, which is printed beside it.

### 117 - A revision is built from the earlier zip

`run` scans the folder for this run's zips (`-<id8>.zip`, `-<id8>-r<N>.zip`, kept only if `report-data.json` inside holds this run id), and once Core answers the revision builds from the highest zip below it: **`measurements.json` and every `streams/*.csv|txt` are read from it, not from Core**, so the PDF is built from the bytes the earlier zip carried and the manifest comparison still decides. The appendix says "supersedes revision N" with the SHA-256 of that zip's `manifest.dsse.json`; with no earlier zip but a revision above 1 it uses Core's copy of the previous manifest and says so. What a republish does after the retention sweep is [decision 126](#126---a-swept-run-is-republished-by-handing-core-the-earlier-zips-own-files). **Measured:** against a mock Core whose capture routes answer `404` for r2. **Not run:** a real swept run.

### 126 - A swept run is republished by handing Core the earlier zip's own files

Core answers `report-data` with `409` for a run whose directory the retention sweep took, naming what to hand back (`embarch-core` decision 120). `run` then takes the highest earlier zip in the publish folder (decision 117's scan) and `PUT`s `/study/{id}/restore/{name}`, raw, one file at a time: `manifest.dsse.json` first, then every subject the manifest names that is a Core file, in manifest order. Core's revision outputs (`report-data.*`, the segment, the manifest) are skipped, since Core does not accept them, and embarch-api's own files are not subjects and are not restored; they are resent with `publish` as usual. Core checks each file against the manifest it logged and answers `409` or `422` otherwise; that refusal is relayed and **nothing is written**, the earlier zip untouched. `report-data` is then asked again and the publish continues as for a run on disk. With no earlier zip the publish refuses, names the folder and the file name it looked for (`-<id8>.zip` or `-<id8>-r<N>.zip`), and writes nothing, and sends Core nothing. The client method is `CoreClient::restore_file` (additive, in the shared `embarch-core-client`; it reuses `study_timeout`, **assumed**, not measured, since a capture can be large). The `409` is matched by status text in the error, like the `404` it replaces. **Measured:** against a mock Core, r1 then a swept r2: the manifest goes first, a capture is handed back byte for byte, the restores precede the second `report-data`, and the earlier zip is unchanged. **Not run:** a real swept run against a real Core.
