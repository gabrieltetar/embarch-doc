## 1. What it is

Three responsibilities on top of `embarch-core`: **(a)** Core's capabilities as MCP tools, **(b)** the same as CLI subcommands — a **superset**, `versions`, `patches`, `stack`, `guide` and `list-studies` have no tool — and **(c)** running a configured build command and feeding the artifact to Core's `/flash`, or its signed MCUboot image to Core's `/bootload`, or packaging the finished build as a flashable bundle for someone with no toolchain ([interfaces/tools-bundle.md](interfaces/tools-bundle.md)).

**Subcommand presence is the mode switch.** No subcommand → an MCP stdio server; a subcommand → run that one operation and exit. Both front-ends call the same modules; neither is privileged.

Core owns all direct hardware access — `probe-rs` and `serialport` live exclusively there, and this crate links neither. **Core has no idea this crate, MCP or Claude Code exist.** `embarch-umbrella` sits on the far side of the same boundary: it writes this crate's config and shells out to its CLI, unknown here.

## 2. Invariants

- **Single user, single Core instance.** No multi-tenancy, permission model or database; each engineer runs their own stack.
- **Core's address is never hardcoded to loopback.** Always a config value — Core is expected to move to a LAN-reachable machine.
- **`build_command` is an argv array, never a shell string** — no quoting or shell-dialect ambiguity. A project needing shell features says so: `["bash", "-lc", "…"]`
- **`chip`, `flash_format` and `base_address` are opaque pass-through.** Not validated against probe-rs's target DB; that's Core's job, duplicating it here is a maintenance trap.
- **A fresh artifact is proven, never assumed.** The artifact path's existence and mtime are recorded *before* spawning; after a zero exit the file must exist and, if it existed before, be newer than the build start — otherwise a build that failed partway could silently "succeed" against a stale binary, the worst failure for hardware bring-up.
- **An expected failure comes back as tool content, not a protocol error**, so a calling agent sees the real compiler error and can reason about it. A protocol error is reserved for this crate's own config being unloadable at all; that exception and the CLI's exit-code shapes are in [tools.md](interfaces/tools.md).
- **A build runs the tree the session is in.** A server whose working directory is a git worktree of the clone a project's `source_path` is in builds that worktree (same relative path, build directory of its own under `build_dir_root`), or refuses at startup naming both trees; anywhere else `source_path` is used as configured. The plan's environment is the project's `env` table over the server's own ([decision 106](decisions/build.md)).
- **This crate never knowingly runs a tree-mutating `git` subcommand**, named directly or behind a shell/exec wrapper. "Reflash" means build and flash the tree **as it stands**, then verify — never "make my tree be that version". Enforced against the config file, not just this code.
- **No inference presented as fact.** Anything about a DUT this crate can't observe is declared by the operator or reported unknown.
- **Every JSON object either front-end emits carries `schema_version`**, stamped in one place rather than per emitter, and there is no `error_kind` ([decisions](decisions/surface.md) 24, 50).
- **The bench lease token rides every Core call, from `EMBARCH_LEASE_TOKEN` or the process's own lease, and a refusal is Core's text verbatim**; a lease Core released for idleness (30 minutes with no hardware call) drops the token and refuses the next hardware call until taken again ([decisions](decisions/lease.md) 90).
- **A session with `EMBARCH_REQUIRE_LEASE` in its environment is refused a hardware route while no lease is live**, before the route is called; with one live, Core decides by the token ([decisions](decisions/lease.md) 101).
- **`bench_exchange` times are Core's receive times when Core sends them, else the poll that first saw the line.** Every answer says which, per signal (`time_basis`) ([decisions](decisions/bench-exchange.md) 89).
- **`run_study` tells Core what it built, as claims** ([decisions](decisions/build-claims.md) 111): the project checkout's commit and dirty state and its `west` version, each sent only when read, none for a build with no git checkout.
- **Every call that reaches a lease-gated route appends one line to `<repo>/embarch/live/<date>-<session>.jsonl`, citing Core's call-log entry by `seq` and hash**, with the board, the image hash and the answer; `--json` carries the entries and `call_log`/`call-log` reads them back. A call with no repo to write to says so ([interfaces/live-log.md](interfaces/live-log.md)).
- **`embarch_api::person_writer` is the one confined writer for the person's `embarch/`**: fixed kinds, each with its own folder and extension, names from `[a-z0-9][a-z0-9._-]{0,99}`, no link followed, atomic by rename, nothing run. No command calls it yet ([decisions](decisions/person-mirror.md) 132).
- **HIL plans and custom suites: `embarch/tests/`** ([134](decisions/test-plans.md)).
- **`run_test` prepares a Test run and never starts one; `test_status` reads it** ([135](decisions/test-run.md)).
- **The hardware test ledger is plain files under a project's `embarch/ledger/`, and the pending view is computed, never stored** ([decisions](decisions/ledger.md) 98). `run_study` appends a `submitted` row; reading the ledger closes it from Core's study result.
- **A report renders to PDF inside this binary, with no `typst` binary and no network, from a root confined to the staged files** (the `pdf` feature). Packages are embedded, a link is refused at staging and again at read, and the same inputs give the same bytes ([decisions](decisions/report-pdf.md) 110; [interfaces/report-pdf.md](interfaces/report-pdf.md)).
- **`publish <run id>` writes a finished Study run as one zip, to a folder the config names and no default supplies**, through Core's publish routes and never Core's disk. The PDF, the appendix, the two exports, `report.typ` and its packages are this crate's and are listed in Core's manifest as such; every other file is Core's, carried as served. Layout: [interfaces/publish.md](interfaces/publish.md); why: [decisions](decisions/publish.md) 112 to 114 and [115 to 117](decisions/publish-revisions.md). The appendix lists every number in the prose and `report.typ` (cited, tagged, unbound, untagged, hardcoded) and each prose block's author; publishing again writes `-r2` from the earlier zip and names its manifest hash.
- **`verify <zip> --public-key <hex>` checks a published zip offline**, with no config and no Core: signatures (check 0), manifest hashes (1), each measurement re-run from the raw captures with the behaviour the signed record names (2, partial), labels (5), both exports regenerated byte for byte (7), the run log's segment and the call log's, against the signed record's range (8), every number the PDF prints matched to the signed data, a measurement, a listing, an axis tick or the footer (4, partial while only the unsigned appendix vouches for one), `report-data.json` recomputed and what the PDF prints of it (6) and `report.typ`'s syntax tree held to a whitelist with every carried package hashed (9). `publish` refuses a `report.typ` the same whitelist refuses. A key not matched by `--attested-fingerprint` says "origin unattested". Interface: [interfaces/verify.md](interfaces/verify.md); why: [decisions 118 to 121](decisions/verify.md), [122 to 125](decisions/verify-report.md).
- **The client sends a token only after Core's challenge checks, picked by the `core-fingerprint` beside the token file**: a match sends the machine-wide token, a mismatch the development token or none, and no file leaves it as it was ([decisions](decisions/client-crate-funnel.md) 133); `status` shows the mode and fingerprint.
- **`core-key` prints Core's public key and fingerprint after checking its signature over a fresh nonce** ([decisions](decisions/verify.md) 129): CLI only, sends no token, writes the key nowhere, so `verify`'s key stays out of band.
- **A live event stream is an optimisation, never the source of truth.** Losing it falls back to polling and is reported, never fails a call. Core's `lagged` frame is a fact to relay, not an error ([decisions](decisions.md) 48).
