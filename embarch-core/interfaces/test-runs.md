# embarch-core: the test-run routes

**Status:** active, 2026-11-25 (`tasks/core/158`, `159` and `160`, [decisions 134](../decisions/test-runs.md), [135](../decisions/test-run-go.md), [136 and 137](../decisions/test-run-executor.md), [139](../decisions/test-run-setup.md), [153](../decisions/test-run-resume.md)). Index: [../interfaces.md](../interfaces.md).

All six are lease-open: the prepare, the status and the card are a file and a rendering, never a port; the go takes the lease itself and the cancel must reach a run that holds it. Errors are plain text. Preparing starts nothing; the go starts the run, and Core's executor runs it ([136](../decisions/test-run-executor.md)).

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/test-runs` | `{run, plan, suite?, studies}`: `run` is `run.json` (`embarch-study-designer`'s `RunJson`); `plan` the hash of a kept `plan`; `suite` the hash of a kept suite manifest, or absent for the premade suite the plan's id and version name; `studies` `{<study.file>: <host study>}` | `201 {run_id, run_hash, lease_holder, duration_bound_ms}`; `422` a definition Core does not keep, a manifest test it cannot resolve, a `plan_hash` that is not the plan's, **a premade study that does not hash to its test's `study.hash`, naming the test, the file and both hashes**, or **a `run.json` it does not reproduce, naming the first differing key**; `409` the `run_id` is already prepared; `400` a `run_id` outside `[A-Za-z0-9_-]{1,128}` or a malformed hash |
| `POST` | `/test-runs/{run_id}/go` | `{run_id, run_hash, nonce}` from the card; **the person's token only on every Core** | `200 {run_id, run_hash, state: "started", started_utc_ms, lease_holder}`; `403` the agent's token; `422` whose first word is `mismatched`, `expired` or `replayed`; `409` already started, an input still unconfirmed (named), or the session that prepared the run no longer holds the lease (a run prepared with no lease is refused too); `404` |
| `POST` | `/test-runs/{run_id}/cancel` | none; either token | `200 {run_id, state: "cancelled", by}`; `409` the run is not the one in flight |
| `POST` | `/test-runs/{run_id}/resume` | `{run_id}`: the id the new run takes; either token | `201 {run_id, run_hash, resumes, lease_holder, duration_bound_ms, pending, kept}`: a new prepared run of the tests the `interrupted` run left with no verdict, its `run.json` carrying `resumes`, cut from that run's own record and not re-expanded; it has its own card and go, and its smoke check reads the images back ([153](../decisions/test-run-resume.md)); `404` no such run; `409` the run was never started, is in flight, ended another way, was already resumed (naming the run that did), has nothing pending, or the new `run_id` is used; `400` a bad `run_id` |
| `GET` | `/test-runs/{run_id}` | none; either token | `200 {run_id, run_hash, state, bench, test, verdicts, waiting_prompt}`; `state` is `prepared`, `started`, `running`, `completed`, `cancelled`, `deadline` or `interrupted` (Core restarted under it; `verdicts` are the tests it had finished); `bench` and `test` name what is running, else `null`; `verdicts` is each finished test `{test_id, bench, verdict, reason, qualifiers, counts, runs: [{verdict, reason}], study_ids, note}` in run order, a skipped or cancelled one with its reason; `waiting_prompt` is `{prompt_id, step, text, bench_config, deadline_utc_ms, kind, observation, switched_on: [{step, target, line}]}` with its strings as `agent_text` (decision 138), else `null`; `404` |
| `GET` | `/test-runs/{run_id}/card` | none | `200 {run_id, run_hash, lease_holder, prepared_utc_ms, card, nonce, expires_utc_ms}`; `nonce` and `expires_utc_ms` are `null` unless the token is the person's; `404` |

`run_hash` is the hash of Core's own re-expansion, in which each capability's and hook's `confirmed` is Core's record; the comparison with the caller's `run.json` blanks `confirmed` on both sides. `lease_holder` is the name of the lease holder when the run was prepared, `null` with none.

**`card`**: `suite {id, version}`, `standard {name}`, `dut {declared_serial, board_revision, capabilities, hooks}`, `stop_on_fail`, `benches [{name, tests}]`, `duration_bound_ms`, `unconfirmed [{kind, name, hash}]` (`suite`, `capability`, `hook` or `test`; read from the run log at each request), and `tests`, each:

| Key | Meaning |
|---|---|
| `test_id`, `title`, `definition_hash`, `requirements`, `precondition`, `run_count`, `step_budget_ms` | from `run.json` |
| `origin`, `diff` | `premade`, `derived` or `custom`; for a copy `{from, fields: [{field, old, new}]}` (the crate's `derived_diff` against the premade test it names) or `{from, unavailable}` |
| `prompts` | `[{list, step, text, kind, bench_config, timeout_ms}]`, `kind` `setup`, `action`, `observation`, `clearance` or `null` |
| `energising` | `[{list, step, target, line}]`: each step `hil_check::energises` says powers something, with the line it sends; `list` is `steps` or `teardown` |
| `limits` | `[{measurement, unit, lower, upper, expect, U, k, w}]`; `U` and `k` from the test's source for the measurement (`null` where it declares none), `w` = `w_multiple` times `U` |
| `decision_rule`, `setup_terms` | `{kind, w_multiple}`; `[{name, unit, U, k}]` |
| `study` | `{file, hash, bytes_checked_against_hash}`; the last is `true` when the prepare hashed the premade study sent (`study_hash`) and it equalled `study.hash`, `false` for an expanded template's study or one not sent |

**Every string a definition, a study or `run.json` wrote is `{"agent_text": "<string>"}`**; a surface escapes it. That includes every string inside a free value — a capability's `value`, a hook's `maps_to` (`{"shell": {"agent_text": cmd}}`), a diff's `old` and `new` — whose object keys stay plain. Numbers, hashes, kinds and Core's own words are plain.

A go nonce is 32 random bytes in hex, single use, ten minutes, in memory, from the store of [definitions](definitions.md); it is issued for `go:<run_id>:<run_hash>`. A prepared run is `test-runs/<run_id>.json` in the store, and a started one also `<run_id>.started.json`.

**While a run is started** the lease is the run's: every lease-gated route is `409` naming the run, the session's token included, and renew and release of the lease likewise; `GET /lease` shows `holder` `test run <id>` and `run_id`. The lease neither expires nor idles, and goes back to the session under its old token, TTL restarted, when the run ends or is cancelled. The run log gains `test_run_started` and `test_run_ended` ([run-log](run-log.md)); each study of the run is a host study in it. **`POST /study/{id}/cancel` is admitted while a run holds the lease**, without a token, and ends the run `cancelled`. The executor keeps `<run_id>.result.json` beside the record when it ends, and `<run_id>.checkpoint.json` (every finished test and smoke check) as each test ends; a run Core lost is sealed at the next start from the checkpoint, and a resume leaves `<run_id>.resumed.json`.

**Between two benches** the executor raises a `setup` prompt, answered at `POST /study/{run_id}/prompt` and shown as `waiting_prompt` (`kind` `setup`, step `setup:<bench>`, text naming the bench, its configuration and what is missing, always empty: the smoke check runs after it, [143](../decisions/smoke-check.md)). While it waits, enrolment, roles, signals, instruments, bootload ports and the dev-bench link are admitted with either token, each entered as `test_run_setup_call` with its scope; every other gated call stays `409`. An agent's answer is recorded `relayed`; a decline or timeout is an `error` on that bench ([139](../decisions/test-run-setup.md)).
