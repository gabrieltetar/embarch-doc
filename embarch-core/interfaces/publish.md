# embarch-core: the publish routes

**Status:** active, 2026-11-26 (`tasks/core/135`, [decisions 116 to 119](../decisions/publish.md); the Test run's two routes, [148, 149](../decisions/test-run-publish.md)). Index: [../interfaces.md](../interfaces.md). Consumer: embarch-api's `publish` (M1.10) and `verify` (M1.11).

All take the token (either) and are lease-open. Errors are plain text. The table is a **Study's** publish; **a Test run's** is [below](#a-test-runs-publish).

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/study/{id}/adopt` | `{"kind": "note"\|"prose", "name": "<relative file name>", "text": "..."}` | `200` the `adopted` `{entry, hash}` (`scope`, `text_sha256`); `400` bad kind or name; `404` no such run; `413` text over 1 MiB |
| `POST` | `/study/{id}/report-data` | none | `200 {revision, report_data_sha256, keyid, report_data}`; `404`; `409` the run has no signed record or was discarded, or its files were swept and not all handed back (the body says which) |
| `POST` | `/study/{id}/publish` | `{"files": [{"name", "sha256"}]}`, embarch-api's own files | `200 {revision, entry, keyid}`; `400` a bad or duplicate name, or a Core-produced name; `409` no `report-data` yet or it changed since (a later adoption, or another token scope than the asker's), or another publish took the revision; `404` |
| `PUT` | `/study/{id}/restore/{name}` | the file's raw bytes, 1 GiB at most | `200 {restored, sha256}`; `400` a bad name; `404` no such run; `409` a file before any manifest, `409` a discarded or unsigned run; `422` a manifest whose hash the run log never recorded for this run, or a file that is no subject of an accepted manifest, a revision output, or whose bytes differ from its digest (decision 120). For a run the retention sweep took: hand back `manifest.dsse.json`, then every Core file it names, then `report-data` and `publish` as usual |
| `GET` | `/study/{id}/publish/{revision}/files/{name}` | none | `200` the bytes of one of the five below or any file the revision's manifest names; **at the pending revision** (the one `report-data` opened, before `publish` signs it) the run's own Core files: `events.json`, `measurements.json`, `study.json`, `record.dsse.json`, `streams/*`, the bytes the manifest will sign; `404` otherwise (any other name or revision, or a revision `report-data` has not opened) |

Files in `study_results/<id>/publish/r<N>/`: `report-data.json` (plain), `report-data.dsse.json`, `run-log-segment.jsonl` (every log line before the publish's entry, as in `GET /run-log`) `call-log-segment.jsonl` and `manifest.dsse.json`. Both envelopes are DSSE v1 under the [signing](signing.md) key.

**`call-log-segment.jsonl`** is written only when the run's record names a call-log range ([signing](signing.md)): a header line `{"call_log_segment": {prev, head, first_seq, last_seq}}` (the entry before the range by its hash, the head at the range's end), then the range's `{entry, hash}` lines as in `call-log.jsonl`, which recompute from `prev` to `head`; an empty range is the header alone. It is `409` if the call log no longer holds the range or does not chain to the recorded head. A run with no range in its record gets no file (`GET` it is `404`).

**`report-data.json`** (canonical, no clock, no run-log head): `schema` 1, `study_id`, `kind`, `revision`, `run_status` (`completed`/`step_failed`), `steps` `{total, pass, fail, timed_out, other}`, `subject` `{study_name, provenance}`, `attestation` `{label, core_mode, release, reason}` (`person's acts not protected` or `agent-scoped only`; `core_mode` and `release` copied from the signed record, `core_attested: false` instead for a record with no `release` key), `go_by`, `published_by`, `adopted` `[{kind, name, text_sha256, scope, attribution, at_utc_ms}]` (`attribution`: `relayed by the agent`, `the person's`, `entered with the agent's token`, `the person's token`), `observed` `{image_status, declarations, call_log}` (`call_log` `{head, first_seq, last_seq, count}` copied from the record's `observed.call_log`, `count` the entries in the range, 0 when `first_seq`/`last_seq` are null; **present exactly when the record carries one**), `claimed` `{build}`, `core` `{version, keyid}`, `record_sha256`. No `tests`, `requirements` or `verdicts`.

**The manifest Statement:** `subject` is every file Core produced, `[{name, digest: {sha256}}]` sorted (`events.json`, `measurements.json`, `study.json`, `record.dsse.json`, `streams/*`, `report-data.json`, `report-data.dsse.json`, `run-log-segment.jsonl`, and `call-log-segment.jsonl` when written), `predicateType` `urn:embarch:predicate:publish-manifest:v1`; `predicate`: `schema`, `study_id`, `revision`, `supersedes` (`{revision, manifest_sha256}` or null), `published_by`, `published_utc_ms`, `core.version`, `run_log` `{head, length}` (the chain the segment holds), `record_sha256`, `report_data_sha256`, `embarch_api_files` `[{name, sha256}]` (listed, **not** vouched for). The `published` log entry adds `manifest_sha256` (the SHA-256 of `manifest.dsse.json`'s bytes), `revision`, `log_head` and `report_data_sha256` to [the run log's entry](run-log.md). A `run` entry also carries `go_by`.

## A Test run's publish

Both lease-open, either token ([decisions 148 and 149](../decisions/test-run-publish.md)). The same two steps, the same DSSE envelopes under the [signing](signing.md) key and the same `published` entry as a Study's, over one run id.

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/test-runs/{run_id}/report-data` | none | `200 {revision, report_data_sha256, keyid, report_data}`; `404` no such prepared run; `409` the run has not ended, has no signed record, a record, result or study record gone or not the file the run log bound, or a study whose captures were discarded (the body says which) |
| `GET` | `/test-runs/{run_id}/publish/{revision}/files/{name}` | none | As a Study's ([decision 150](../decisions/test-run-publish.md)): `200` the bytes of one of the five publish files above or any file the revision's manifest names that Core made (`run.json`, `result.json`, `test-run.dsse.json`, `studies/<study_id>/<name>`); **at the pending revision** the run's own files, the ones the manifest will sign; `404` otherwise (any other name, a climbing name, a file embarch-api made, another revision) |
| `POST` | `/test-runs/{run_id}/publish` | `{"files": [{"name", "sha256"}]}`, embarch-api's own files | `200 {revision, entry, keyid}`; `400` a bad, duplicate or Core-produced name; `409` no `report-data` yet or it changed since (a verdict, a declaration or a run on the unit entered, or another token scope), or another publish took the revision; `404` |

Files in `test-runs/<run_id>.publish/r<N>/`: `report-data.json`, `report-data.dsse.json`, `run.json` (the canonical bytes whose hash the run's record names), `run-log-segment.jsonl`, `call-log-segment.jsonl` (when the run's record names a range) and `manifest.dsse.json`. Served by the route below.

**The manifest's `subject`:** each study run's Core files as `studies/<study_id>/<name>` (`events.json`, `measurements.json`, `study.json`, `record.dsse.json`, `streams/*`), `run.json`, `result.json`, `test-run.dsse.json`, `report-data.json`, `report-data.dsse.json`, `run-log-segment.jsonl` and `call-log-segment.jsonl`; the predicate is a Study's with `run_id` in place of `study_id`. The `published` entry carries `run_id` and no `study_id`.

**`report-data.json`** (`kind: "test_run"`, no clock, no log head): `schema` 1, `run_id`, `revision`, `run_status` (`completed`, `cancelled`, `deadline` or `interrupted`), `reason`, `resumes`, `suite` `{id, version, commit}`, `standard` `{name, revision, requirement_count: null, atlas: {joined: false, note}}`, `unit` `{unit_key, identity_read, declared_serial, board_revision, declared}`, `person`, `go_by`, `published_by`, `statement` (the fixed pre-compliance sentence), `attestation` (as a study's), `summary` `{verdict, counts, qualifiers}`, `requirements` `{<id>: {verdict, counts, qualifiers, n_of_m, skipped, relayed_listed_apart, tests, skipped_tests: [{test_id, reason}]}}` (verdicts are the crate's roll-up; `not_verified` is one), `tests` `[{test_id, bench, definition_hash, requirements, verdict, reason, qualifiers, counts, runs, note, dut_image, decision_rule: {kind, w_multiple}, limits: [{measurement, unit, lower, upper, expect, rule, w_multiple, u, k, u_declared, w}], study_ids}]` (`u` and `k` are the test's declared source, null with `u_declared: false` where none: [154](../decisions/test-run-publish.md)), `manual_verdicts` `[{log_index, test_id, definition_hash, verdict, reason, note, dut_image, scope, relayed, counted, in_run, at_utc_ms, attribution}]`, `not_run` `[{source: "run"\|"selection", test_id, reason, status?}]`, `coverage` `{tests_in_run, tests_judged, tests_skipped, tests_not_reached, selection}`, `runs_on_unit` `[{test_id, requirements, dut_image, definition_hash, runs: [{run_id, verdict, log_index}]}]` (every `test` entry on the unit, failed ones included), `rules` `[{name, behaviour}]`, `core`, `record_sha256` (the run's record), `study_ids`, and `call_log` as a Study's. Resumed pairs are not published as one ([149](../decisions/test-run-publish.md)).
