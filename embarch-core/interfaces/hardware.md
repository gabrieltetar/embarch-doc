# embarch-core interfaces: Hardware

**Status:** active, 2026-09-07. Split out of [../interfaces.md](../interfaces.md) on 2026-09-07 (`tasks/core/020`) when that file reached its size cap — a reference table, not cut, per [../DOC-COMPACTION.md](../../DOC-COMPACTION.md) §3.

Index: [../interfaces.md](../interfaces.md). Conventions and rationale: [../interfaces.md](../interfaces.md), [../decisions.md](../decisions.md).

| Method | Path | Body / Query | Response |
|---|---|---|---|
| `GET` | `/status` | — | `{ status: "ok", probes: [ProbeInfo], study_designer_schema_version: u32, core_version: String, binary_sha256: String? }` — **the whole field set, and a test on `StatusResponse`'s serialized keys fails if a field is added or removed without this row moving.** `study_designer_schema_version` is `embarch-study-designer`'s **host type** constant, the one guarding this hop. `core_version` is Core's own crate version, compiled in from `CARGO_PKG_VERSION` — the same string `embarch-core --version` prints; **warn, not refuse**, on a skew from it (decision 13). There is deliberately **no** `contract_version`; decision 13 has why. `binary_sha256` is a lowercase-hex SHA-256 of this process's own `std::env::current_exe()` bytes, hashed once at first request and cached — a content identity `core_version` can't give, since two builds can share one crate version (decision 67, decision 68). `null` if the exe's own path couldn't be read back; `/status` still serves normally in that case. `probes` re-enumerates fresh on every call — cheap descriptor enumeration, no attach, which is why a UI can poll it |
| `POST` | `/flash` | JSON `{chip, firmware_path, format, probe_serial?, base_address?, erase?, manifest_path?}` **or** `multipart/form-data` with the same fields plus a `firmware` file part and an optional `manifest` part | `{ flashed: true, chip }`, with the target reset and running the new image (decision 82). `base_address` is hex or decimal, meaningful only for `format = "bin"` and silently ignored otherwise; a `bin` image with **no** base address is refused rather than defaulted to `0`. `erase` never becomes a chip erase in any backend (decision 36). The manifest is parsed **before** the flash and stored **after** it succeeds, keyed per chip; a flash carrying none *clears* that chip's |
| `POST` | `/reset` | `{chip, probe_serial?}` | `{ reset: true }`. Fires a real hardware pulse where the probe supports one, falling back to assert/deassert, then `Core::reset()` |
| `POST` | `/live/mem-read` | `{role? ("dut"), ranges: [{address, words}]}` (≤ 32 ranges, ≤ 256 words, addresses multiples of 4) | `{role, chip, probe_serial, ranges: [{address, words: [u32]}], halted, halted_us}`: reads every range under one halt of a running core, then lets it run (decision 81). `400` bad request, before `hw_lock`; `404` role not enrolled; `409` no probe for it; the identity gate's statuses as `/reset`. Takes `hw_lock` |
| `POST` | `/bootload` | `multipart/form-data`: an `image` file part (required), `entry_command?`, `entry_line_ending?` (`lf`/`cr`/`crlf`, default `lf`), `image_index?` (default 0), `buffer_size?` (the DUT's `CONFIG_BOOT_SERIAL_MAX_RECEIVE_SIZE`). A blank field counts as omitted | `{ bytes, requests, duration_ms, upload_ms, entered_via: "already-in-bootloader"\|"shell-command", bootloader_port, app_reappeared: bool? }` — `app_reappeared` is `null` when no application identity is declared. **`400`** for anything not an MCUboot image with a SHA TLV, checked before `hw_lock`; **`404`** with no ports declared; **`409`** for a port a study tap holds, an ambiguous identity, or no way into the bootloader; **`502`** when the DUT did not do its part — did not enumerate, an SMP error or timeout, a failed reset — carrying what the bootloader printed. Decision 77 |
| `PUT` / `GET` / `DELETE` | `/bootload/ports` | `PUT` `{app?: UsbPortId, bootloader: UsbPortId}`, `UsbPortId` = `{vid, pid, serial?, interface?}` | `PUT` echoes the stored `BootloadPorts` (`{role: "dut", app?, bootloader}`), **`400`** for a pair one port could match both of; `GET` returns it or `404`; `DELETE` is `204`, or `404` when nothing was declared. The role is always the DUT's (decision 78) |
| `GET` | `/serial-log` | `?port=&baud=115200&duration_ms=2000` | `{ port, lines: [String], truncated }` — a bounded snapshot, not a stream. **Meant for dev-bench's link, not a DUT's own console**: plenty of real DUTs have no wired console at all in the configs that matter. `duration_ms` over `serial::MAX_DURATION_MS` (10,000) is a `400` naming the cap and the value given, checked before `hw_lock` is taken (`tasks/core/009`); the capture itself is also byte-capped (`EMBARCH_SERIAL_LOG_MAX_BYTES`, default 1 MiB), and `truncated: true` says the byte cap cut it short rather than the caller silently getting a partial capture |
| `POST` | `/resolve-chip` | `{soc: "nrf54l15"}` | `{chip: "nRF54L15"}`, or `404` naming the SoC. Case-insensitive exact match, no fuzzy matching, and the result is checked against probe-rs's own registry so a stale table entry fails like an unmapped SoC. The 404 names the remedy: `chip-list` for the target name, then a `SOC_TO_CHIP` source edit and a rebuild — the table is compiled in, with no config path ([../decisions/probes.md](../decisions/probes.md) 8, 34) |
| `GET` | `/serial-ports` | — | `[DetectedPort]` — every USB serial port this machine enumerates, unnarrowed. Ports reporting no USB serial are omitted, since a `Direct` route is declared *by* that serial. Empty list is a `200`. Deliberately **not** `/dev-bench/port` with the filter off: that applies a VID gate, and a signal wire's bridge can carry any VID |
| `GET` | `/dev-bench/port` | — | `DetectedPort` (`DevBenchPort` is a type alias for it) — the one USB serial port matching dev-bench's SEGGER VID. Takes no `hw_lock`: descriptor enumeration only, same as `/serial-ports`. `404` when nothing matches (bench unplugged, an expected state); `500` on a genuinely ambiguous match or an unreadable USB bus |
