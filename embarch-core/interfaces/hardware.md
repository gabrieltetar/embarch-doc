## `flashed-images.jsonl` (decision 93, `core/150`)

Beside `run-log.jsonl` in Core's store (decision 129; the data folder unless `--service` or `--store`), one JSON line appended per successful `POST /flash` and `POST /bootload`, after the call has its call-log entry. The latest line per `chip` is what Core flashed there; Core reads the file at start, so a restart keeps it and `GET /status`'s `last_images` (shape unchanged) is built from it. A line from before a start stays, and says what Core flashed, not what the chip holds now (decision 12): a readback decides. A line that does not parse is skipped. A failed append is logged and the flash still answers.

Fields: `chip`, `probe_serial?`, `role?` (`/flash`: the enrolled role of the probe, `null` if none; `/bootload`: `dut`), `path`, `sha256?` (the bytes read just before flashing, `null` if unreadable), `flashed_at` and `at_utc_ms` (one instant), `lease_holder?`, `identity?`, `segments?` (study-designer's `hil-image` `image_segments`: `{address, length, sha256}`, sorted), `scope` (`agent`/`person`, the token that flashed), `call_log_seq?` (that call's call-log `seq`, `null` if the log could not enter it). The first six are `FlashedImage`'s names, kept; `role`, `identity`, `scope`, `at_utc_ms` and `call_log_seq` are new, and `probe_serial` is the task's name already used.

`identity` and `segments` are `null` when Core has no reading: format `uf2` or `idf`, bytes that do not parse, and **every bootload**, since a signed image goes to an MCUboot slot whose address Core is not given (a readback has nothing to compare there). `hex`/`ihex`, `elf` and `bin` (with `base_address`) are read.
