# embarch-core spec: Signing, run log, publish and measurements

**Status:** active, 2026-11-24. Moved verbatim out of [../spec.md](../spec.md) §2's first invariant on 2026-11-24 (`tasks/core/151`, carrying `tasks/core/147`) when that file was in reserve; reference text, not cut, per [../../DOC-COMPACTION.md](../../DOC-COMPACTION.md) §3.

Index: [../spec.md](../spec.md) §2.

**Core signs each study run's record** with an Ed25519 key beside the token files (`signing-key`): `record.dsse.json`, a DSSE envelope over an in-toto Statement naming every capture, `events.json`, `study.json` and `measurements.json` (decisions 113, 131: a host study's parsed numbers) by SHA-256, its predicate keeping what Core observed apart from what embarch-api claimed ([decision 110](../decisions/signing.md), [interfaces/signing.md](../interfaces/signing.md)). **A hash-chained run log** (`run-log.jsonl`, never swept) holds an entry per run, publish and discard, and retention sweeps no unpublished run's captures, and nothing at all while the log cannot be read ([decision 111](../decisions/run-log.md)). **At publish Core signs a manifest and a `report-data.json`** under the same key, takes notes and prose through a route that records the token's scope and the text's hash, and records the log's head beside the manifest hash, and **takes a swept run's earlier files back** through `PUT /study/{id}/restore/{name}`, each checked against a manifest it signed and logged ([decisions 116 to 120](../decisions/publish.md), [interfaces/publish.md](../interfaces/publish.md)). **A finished run's `measurements.json` is read back as written** by `GET /study/{id}/measurements`, with no publish ([decision 121](../decisions/measurements.md)).
