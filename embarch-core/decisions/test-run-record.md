### 144 — A Test run is signed as it ends, entered in the run log per test and as a whole, and its studies are held and swept as one unit

**The record.** `test-runs/<run_id>.test-run.dsse.json`, the same DSSE envelope and canonical serialisation as a study record (110), with `predicateType` `urn:embarch:predicate:test-run:v1`. The executor signs it after the last test and before it releases the run lock, whichever way the run ended: `completed`, `cancelled` (a token's cancel ends the lease at once, and the executor still runs to its end and signs) or `deadline`. Subjects are `run.json` by its canonical hash (the file is not kept as such) and `result.json` by file hash. The predicate carries `run_id`, `status`, `reason`, `ended_utc_ms`, `unit_key`, `resumes` (absent when the run resumes none), `selection` (the `SelectionRecord` the prepare expanded and kept), `observed.call_log` (the study record's shape, 110) and `tests`, one per selected test in `run.json`'s order: `test_id`, `bench`, `definition_hash`, `requirements`, `verdict`, `reason`, `note`, `dut_image` and `study_records` (`[{study_id, record_sha256}]`, null hash when a study left no record). A test with no result carries a null `verdict` and `reason` `not_run`. A failed signing leaves the log entries below with a null `record_sha256` and an error in Core's log; it never stops the run ending.

**Interrupted.** A run Core's restart left (`<id>.started.json`, no result, no record) is sealed at the next start as `interrupted`, before the first request: every test null with `reason` `interrupted`, no study records, since what the executor knew died with it. A resumed run's record names it in `resumes` and the report reads the earlier one; Core does not merge them.

**The log entries.** Per test `{type: "test", run_id, test_id, definition_hash, requirements, unit_key, dut_image, verdict}`, then one `{type: "test_run", run_id, status, record_sha256, study_ids, at_utc_ms}`. None has a `study_id`. `unit_key` is the first bench's DUT hardware ID (143), null when none was read. `dut_image` is the DUT's image status (`holds`, `differs`, `claim`) the smoke check read on the test's bench, null when that bench was never checked. `verdict` is the test's.

**Retention.** The study ids in a `test_run` entry are one unit. They stay protected until a `published` entry names the **`run_id`** (no route writes one yet: Core's side of publish for a Test run is a later unit), even when a study is published alone; `discard` still ends a single study's protection. Once released they count once toward `keep` and go or stay together by their newest member's place (`run_log::retained_in_units`). Until the publish route exists a Test run's captures are never swept; that is the stated rule, not an oversight.

**Not here.** The per-test study record: [145](#145--a-study-record-sealed-for-a-test-names-the-test-its-verdicts-and-what-it-ran-against).

**Measured:** unit tests over the real `drive`, a signing key and a run log: a run cancelled on its second bench signed with a verdict or reason on every test and verifying under an independent DSSE check; the per-test and whole-run entries; an interrupted run sealed once; a Test run's studies held after a solo publish and released by the run's; a Test run counted as one unit. **Not run:** the native Windows build (the owner's debt; nothing here is `cfg(windows)`), and a real run on a bench.

### 145 — A study record sealed for a test names the test, its verdicts and what it ran against

`tasks/core/170`, EMB-369; `notes/hil/03-test.md`, "A run", item 10. The study is sealed before it is judged (110), so Core **amends** each study record when the run ends and **before** the run's own record hashes it (144): `Sealer::amend_for_test` keeps every byte of the Statement, adds `predicate.test`, adds `run.json` (its canonical hash) to the subjects, sorted among them, and signs again. A study run outside a Test run is never amended. The record verifies as before.

`predicate.test`: `run_id`, `test_id`, `bench`, `definition_hash`, `run_index` and `run_count`; `run` (this study's `{verdict, reason, qualifiers}`; null for a study with no judged run, as one Core could not run) and `verdict` (the test's); `note`; from the bench's smoke check (143) `unit_key`, `images` (DUT and each bench board: status and its reason), `identities` (hardware IDs) and `instruments` (each `*IDN?` reply), all null for a bench never checked; `prompts` (per prompt step of the study's `events.json`: `list`, `step`, `prompt_id`, `detail`, `answered_by`, `answered_scope`, the token's scope, 138). `observed.behaviours` stays where 110 put it.

**Binding.** The amended file's hash is bound in the chain by the `test_run` entry: [146](#146--a-test-runs-test_run-entry-binds-each-studys-amended-record-hash-the-amend-stays).

**Not built:** a hello line's reply is not carried. An amend that fails is logged and leaves the record as sealed, without `test`.

**Measured:** a unit test over the real `drive`, `seal` and a key: the amended record verifies under the independent DSSE check, equals the sealed one but for `test`, and the run's record names the amended file's hash. **Not run:** a bench.

### 146 — A Test run's `test_run` entry binds each study's amended record hash; the amend stays

`tasks/core/173`, EMB-579. Decision 111 chains a study's `record.dsse.json` hash in its `run` entry when the study ends, and 145 then re-signs that file at the Test run's end. The `run` entry cannot be rewritten, so for a study made inside a Test run it holds the hash of a file that no longer exists. Two ways out, and **the amend stays**:

- **Remove the amend** and carry the verdicts only in the Test run's own record (144). Rejected: the study's own record is what a study is published and handed on as (`notes/hil/03-test.md`, "A run", item 10), and a verdict beside it that the signed study does not state is an unsigned claim about the study. Re-signing is safe because the Statement is kept byte for byte, the key is Core's, and the amended record is bound in the chain; it is a second signed state of one file, not a forgery of the first.
- **Bind the amended hash** (chosen). The `test_run` entry (144) gains `study_records`: `[{study_id, record_sha256}]`, one per study run the Test run made, each hash taken **after** `amend_studies` ran (null when a study left no record). `study_ids` stays, derived from it, and retention still reads it. The entry is appended after the amends, so the chain recomputes over every entry as before and no entry is rewritten. A study's `run` entry keeps the sealed hash it saw, which is true of the file at that moment.

**The binding entry of a study's record** is the latest `test_run` entry whose `study_records` names it with a non-null hash; failing that, its `run` entry (a plain study, or a Test-run study whose amend or signing failed, where the file is still as sealed). That is `RunLog::bound_record_sha256`. Readers of a record's logged hash and what each reads now: `GET /study/{id}/log` answers it as `record_sha256` beside the `run` entry; `report-data.json`'s `record_sha256` (publish, 118) reads it; publish's check that a study is signed still reads the `run` entry's non-null hash, which is true either way. A Core that stops after the `run` entry and before the `test_run` entry leaves the sealed hash bound and the file amended or not; the run is then sealed `interrupted` at the next start (144), and its studies are not amended.

**Measured:** unit tests over the real `drive`, `seal`, a key and a run log: the `test_run` entry's study hash equals the amended file on disk and `bound_record_sha256` returns it; a plain study is bound by its `run` entry, then by a later `test_run` entry once its file is replaced; the chain verifies. **Not run:** a bench.
