### 136 — Core's executor walks a started run bench by bench and judges each test with the shared crate

**After the go**, `test_executor::spawn` runs the executor on its own blocking thread (`AppState::run_executor`, on in service, off in unit tests whose go has no bench). `drive` walks `run.json`'s benches in order and each bench's tests in order against an `Env`, so every path of the policy is tested over a fake and `CoreEnv` is the only part that touches a bench. **The study a test runs is the one the prepare kept** in the record (`studies` by `test_id`, as the card read it), not one fetched by hash: Core keeps no study (134), so the bytes are still unchecked against `study.hash`. A test with no kept study is an `error`.

**The precondition runs once before every test**, not before each run of it. `reset` resets the DUT through the reset path (`hardware::reset` on the enrolled DUT, under `hw_lock`), then sends each bench board's `idle` line through the exchange route's body. **Assumed**: the board's signal is named by its `part`, and since `run.json` carries no `until` for `idle` the wait is a 500 ms quiet read, so a lost port fails it. `none` does nothing. **`power_cycle` and `detach` are an `error`**: `run.json` carries only `idle` and `hello`, so Core has no line to send and does not skip silently. A failed precondition is an `error` (`bench_step_failed`).

**Each run** is `host_study::run_study_blocking`: the same body as `POST /host-studies` without the route (`study_lock`, taps, cancel slot, `run_job`, teardown, seal), the run logged as a host study. Its `events.json` and `measurements.json` are read back into the crate's `StepRecord` and `MeasurementRecord`. **A step's target is Core's** (`target_of`): a signal whose origin is the `dut` role is `dut`; another role, a bench board or an instrument is `bench`; an undeclared signal is `dut`, as `measurements.json` reads it. A step a cancel cut short is not judged. **`judge_run` then `judge_test`**, `Rules::latest()`, with `U` from `run.json`'s source and a measurement with no source flagged `calibration_undeclared`. Bench-board values read `unverified` (no image readback, 03 item 3); the DUT's are `DutReport`. **`calibration_expired` is never set and is not checked for a person's choice**: it is an instrument's lapse, which `judge_run`'s `expect` path does not read and a choice has none; Core records no observation's choice yet, so an `expect` limit reads `record_gap`, `inconclusive`.

**The policy**, in precedence: a cancel ends the run (every remaining test `cancelled`); `stop_on_fail` after a fail (`stopped_after_fail`); an error earlier on the bench (`stopped_by_error`; the next bench still runs); a `requires` that did not pass (`requires_not_met`). A fail ends only its test; `inconclusive` ends nothing; an error ends the test's remaining runs. A test's verdict is its worst run with counts, so three runs with one fail are `fail`, `2 pass, 1 fail`.

### 137 — A cancel ends the run through the executor, a deadline bounds it, and `GET /test-runs/{run_id}` says where it is

**Cancel.** `POST /test-runs/{id}/cancel` ends the run and sets the in-flight study's cancel flag, so the step finishes and the teardown runs. **`RUN_ADMITTED` names `/study/{id}/cancel`** (135's note): admitted whole while a run holds the lease, no token asked, and the flag it sets ends the run `cancelled` through the executor. Every other gated call stays `409`.

**The deadline** (135's open point): `2 * duration_bound_ms + 120 s` per test, **chosen, not measured**. Past it the rest are `cancelled` and the run ends `deadline`. A study past its own timeouts is not interrupted.

**`GET /test-runs/{run_id}`**, either token, lease-open: `state`, the current `bench` and `test`, `verdicts` so far, and the `waiting_prompt` with its text as `agent_text`. At the end the executor keeps `<run_id>.result.json`, which the route reads after; a started run with no progress and no lease is `interrupted`.

**Host studies only in this phase.** Running dev-bench studies in a Test run is the alternative: **the owner's to strike (plan choice 18)**, and it changes `Env::run_study`, not the policy.

**Open.** A Core restart mid-run is sealed `interrupted` ([153](test-run-resume.md)); the between-bench setup is [139](test-run-setup.md), the smoke check is [143](smoke-check.md); a measurement repeated in a `Repeat` is read by its first record; the board-signal and idle-wait assumptions above.

**Measured:** unit tests over a fake bench for each policy path (a fail goes on, an error ends its bench, a cancel, `stop_on_fail`, `requires_not_met`, three runs with one fail, a lost port on a board against `until_not_seen` on the DUT, a deadline), the step and measurement mapping, the status during a held test and after, and the study cancel admitted under a run. **Not run:** the real reset, idle and study path on a bench (**debt**: one run of a two-test fixture suite on a bench with a DUT and a board, in the person's session), and a native Windows build.
