### 134 — Core re-expands a run and registers it prepared, and renders the go card from its own record

**`POST /test-runs`** (either token) takes `{run, plan, suite?, studies}`: `run.json`, the hash of a kept plan, the hash of a kept suite manifest (absent: the premade suite the plan names) and the study files. Core resolves each manifest test from its store or its premade suites, calls the crate's `hil_expand::expand` and compares `RunJson::hash()`. **A `run.json` it does not reproduce is `422` naming the first differing key**, array elements named by `test_id` or `measurement` (`tests[t].limits[vbus_mean].upper`). A reused `run_id` is `409`; the id is a file name (`[A-Za-z0-9_-]`) and the record is hard-linked into place, so two prepares of one id cannot both win. **A prepared run** is `test-runs/<run_id>.json`: Core's own re-expansion, its hash, the card's static data, and **the session's lease holder at that moment** (a name; none is `null`, and the go refuses that, not this). Nothing is started, powered or leased.

**`GET /test-runs/{run_id}/card`** (either token) serves the card from that record: tests per bench; each test's origin (`premade`, `derived` with `derived_diff` against the premade test, or `custom`); every prompt with its kind; every energising step with its line (`hil_check::energises`); every limit with `U`, `k` and `w` (`w_multiple` times `U`); and `duration_bound`. **Every string a definition, study or `run.json` wrote is `{"agent_text": s}`**, so a surface escapes it. **Inputs still unconfirmed are listed as the log stands at the request**: the suite manifest, each capability and hook, each unconfirmed test. **An unconfirmed input does not refuse the prepare**; the go will.

**The go nonce** is in the card for the person's token only. It is decision 133's store unchanged (32 random bytes, single use, ten minutes, in memory, a wrong try spends it), keyed `go:<run_id>:<run_hash>`, so a confirmation's nonce cannot spend a go's. Each request issues a new one; older ones live until spent or expired.

**`confirmed` in `run.json`** is Core's record, which the caller cannot write or read, so the comparison blanks it on both sides and the registered run carries Core's. So its hash includes the confirmations at the prepare: one made after leaves it stale; the go keeps the prepared hash ([135](test-run-go.md)).

**The owner may strike two choices.** Plan choice 9: the caller writes `run_id` and Core refuses a reuse (Core assigning it is the alternative). Plan choice 10: the go's nonce is single use and lives ten minutes.

**Not here:** a run-log entry for a prepare (the go is [135](test-run-go.md)); **a check of the study files against `study.hash`**: the crate fixes no hash for a premade study file, so the card's prompts and energising steps rest on what the caller sent (`bytes_checked_against_hash: false` says so); the saved benches, which Core cannot list, so **the benches that exist are assumed to be those `run.json` uses**. **Measured:** unit tests register a reproduced run, serve its card with each token (the nonce spends once and only for this run), refuse one edited limit by name and a reused id, and list an unconfirmed input until the person confirms it. **Not run:** a native Windows build.
