### 135 — The person's go moves the session's lease to the run; a run lock guards the gaps between its studies

**`POST /test-runs/{run_id}/go`** is the person's token only, on every Core: `403` to the agent's (`token_store::GO_ROUTES`), before any lease check. The body is `{run_id, run_hash, nonce}` from the card. Refusals say which: **`422` `mismatched`** (a body id or hash that is not the route's or Core's, or a nonce for another card), **`422` `expired`** (past ten minutes), **`422` `replayed`** (unknown, used or from before a restart: the store cannot tell these apart). `409` for a run already started (a run starts once, `<id>.started.json`, even after a cancel), an input the card lists as unconfirmed (read from the log at the go, named), or a session that no longer holds the lease. **The nonce is spent only when nothing else would refuse the go**, so an unconfirmed input costs no card; a wrong try still spends it (133).

**The go does not re-expand.** The hash registered at the prepare stays the run's identity (the nonce is keyed on it) (re-expanding needs the study files, which Core does not keep). A confirmation made since is read live at the go and is not folded into `run.json`: **the run's `confirmed` fields stay as prepared**, and whoever reports the run (EMB-366's executor) reads the confirmations from the run log. This closes decision 134's open choice.

**The lease moves to the run.** The session's lease stays in its slot; `AppState::run_lock` (`lease::RunLock`, the run id) is set under the slot's own mutex. While it is held `LeaseSlot::admit` refuses every token, the session's own included, `lease_middleware` refuses every gated route `409` naming the run (`lease::run_refusal`), renew and release are refused the same (the session cannot give away what the run holds), and `GET /lease` shows `holder` `test run <id>` with `run_id`. **The lease neither expires nor idles** while the run holds it, so a run past 30 minutes (`IDLE_RELEASE`, 123) or past its TTL keeps it. **At the end it returns under its old token with its TTL and idle clock restarted** (`LeaseSlot::end_run`). The go needs the lease **of the session that prepared the run**: the holder recorded at the prepare must still hold it. A run prepared with no lease, or a released, lost or reassigned lease, is refused naming which; take a lease and prepare again. Reads of a run (`GET /test-runs/{run_id}/card`) stay open.

**`POST /test-runs/{run_id}/cancel`** takes either token, is not lease-gated (a run holding the lease would refuse its own cancel), ends the run and gives the lease back. `409` when `run_id` is not the run in flight, naming it if another is. **The run log** gets `test_run_started` (run, hash, the go's scope, the session) and `test_run_ended` (`status`, `reason`, `scope` of the cancelling token, `core` when the executor ended it); neither has a `study_id`.

**The seam for EMB-366.** `test_runs::end_run(state, run_id, status, reason, by)` is what the executor calls when its studies are done, and is what a cancel calls. `RUN_ADMITTED` in `api.rs` names the gated calls a run still admits ([136](test-run-executor.md)); a prompt's answer needs none, `POST /study/{id}/prompt` is lease-open. The executor stops when the run lock clears (a cancel) and holds `study_lock` per study.

**Open.** A Core restart mid-run drops the run lock and the lease (both in memory): [153](test-run-resume.md) seals the run `interrupted`. A run holds the lease with no timeout of its own, so a run whose executor dies without calling `end_run` holds the bench until it is cancelled; the executor owns a deadline from `duration_bound_ms`.

**Measured:** unit tests for each refusal, the session's `/reset` `409` naming the run and admitted after the end, a cancel from each token with its scope logged, and a lease held past two idle windows and its TTL. **Not run:** a native Windows build (a worktree cannot build it), and no hardware is touched.
