| 51 | An async-UART Kconfig defaulting `y` with the right dependency makes checking the generated `.config` a formality → **the check was the point, and it failed the first time.** The per-instance async symbol depends on that instance *not* being interrupt-driven, which defaults on whenever the global is — **which the BLE-shell snippet turns on.** Dropping the per-instance override as redundant compiled the UART interrupt-driven, **the async symbol vanished with no warning**, and the tracer would have fallen back to the per-byte loop that burns exactly the CPU time it exists to measure. **The module's own symbol stayed `y` throughout** | outpost |
| 52 | Manifest pinning versus an extra-modules CMake define is a plumbing choice — same module, different plumbing → **for a project built through `embarch-api` the pin is mandatory and the define unreachable**: passthrough args are inserted *before* west's own, so a separator terminates the wrong argument list and the build dies before configuring | outpost |
| 53 | Threads and CPU idle are mutually exclusive, so a load repartition can sum them against the capture window → **idle is reported twice by construction, and summing claimed 1,338,800 cycles of a 760,000-cycle window.** Zephyr's idle thread appears both as idle records *and* as ordinary switches of the thread the manifest names idle. The two are now allowed to **disagree**, with the disagreement surfaced rather than averaged away. **Found by writing the assertion and watching it fail, which is the only reason it was found: both numbers are individually plausible** | ui 10 |
| 54 | `probe-rs` is a fine single flashing backend for every target, and the chip-erase incident was an erase-path problem fixed by not chip-erasing → **Core was overriding the board's own declared programming method for every operation.** The board names three real flashers, with the debug speed already filled in; Core used none. The mechanism row 19 declined to guess at is now clear: **this part stores code in RRAM, not the NVMC flash every older part uses**, and the target description models no RRAM granularity **for any operation, erase or not.** The empirical record agrees — across a whole phase, no image Core flashed to this DUT was ever demonstrably running | core 36 |
| 55 | Row 28's delegation to the vendor tool shipped → **it was never implemented, and the doc recorded a rejected option as the shipped one for two days.** Caught by that decision's own correction note, **then deliberately not acted on** — changing which mechanism ships was not that session's call — and it stayed unbuilt across three further sessions of flashing this DUT. **A decision recorded as settled, with its own note saying it is unbuilt, is indistinguishable in a later reader's eyes from one that shipped** | core 32 |
| 56 | A non-zero return from the security request means the elevation failed → **"busy" means a security procedure is already in flight, and reporting it as failure blames the wrong side.** The first real study failed its security step and **the next step then ran at the requested level.** The decision had predicted the DUT self-elevates after connect and handled "already at or above"; it did not handle *arriving in the middle of one.* Two attempts rather than a retry loop, because the failed call resets the required level | bench 37 |
| 57 | A directory containing an `embarch/` subdirectory is a firmware repo → **it accepted `$HOME`**, because this bench's suite parent folder is `~/embarch`. Tightened to require something the tooling actually wrote there. **The rule was reasoned carefully to avoid rejecting the legitimate first-time state, and over-corrected into accepting anything** — found in the first thirty seconds of pointing it at a wrong path | ui 14 |
| 58 | Writing the deploy procedure down would stop it being re-derived every session → **it stopped it being *forgotten* and did nothing about it being *re-typed*.** Every deploy for two weeks after was still a hand-assembled sync loop and a from-scratch elevated script. **A documented multi-step manual procedure with a silent failure mode in the middle of it is a command waiting to be written, and prose cannot carry the verification step that justifies the command** | umb 32 |
| 59 | `CONFIG_LOG=n` was the right implementation of "no unframed text on a shared binary link" → **the decision forbids unframed log *text* on the wire, not the logging subsystem, and reading it as the latter cost three weeks of a blind bench.** A backend that emits framed log records satisfies it exactly. Every error log in the BT host and the entire fatal dump compiled to nothing. **A decision constraining a *mechanism* can be implemented as though it banned the *capability*, and the wrong reading looks identical to the right one in the Kconfig** | bench 38 |
| 60 | The C5's RAM segment is simply full, so a feature needing ~11 KB must be trimmed until it fits → **~10.5 KB of it was one buffer sized for a message that cannot arrive**: inbound frames were staged at a bound set by a message dev-bench only ever *sends*. The other half is where the 11 KB went — **~5.1 KB is *code*, forced into IRAM by the vendor's own linker script, which no Kconfig trimming reaches.** Found by diffing RAM reports after four hand estimates were each wrong in a different direction | bench 38 |
| 61 | Holding the boot log until the first handshake and flushing it behind the ack gets that record to Core → **the handshake endpoint returns the instant it has the ack and drops the link, so on a freshly reset bench the boot record was flushed onto a wire nobody was reading** — and every later handshake had nothing left to flush. **Reliably produced and reliably lost, which is worse than absent.** Found by looking for a line that should have been there; the build, the tests and the firmware were all correct | core 37 |
| 62 | An absolute cycle read in every record is worth its cost — argued twice, priced, re-priced, and built → **the cost was in the wrong place.** The read sat *inside the context switch and inside the ISR wrapper*: **the instrument charging its cost to the exact path it measures**, the same objection already used to refuse a lock there, applied one level down and not noticed. Layout 2 removed every timestamp, **and ISR duration stopped being measurable at all.** The decision had been re-argued and re-priced **without anyone asking *where* the cost landed** | outpost 4, 17, 18 |
| 63 | A slot-size constant describes the ring slot it sizes the ring by — asserted in a comment, divided into the ring bytes, and pinned by a unit test → **the slot was 25% larger, so every ring had been 1.25× its configured size since the module was written.** The test asserted a relation between *constants* and said nothing about the struct. **Row 44's shape again: a hand-mirrored constant guarded by a comment and a test written in the constant's own terms** | outpost |
| 64 | The load repartition shipped working — built, unit-tested against a real capture, six tests green → **it had never once rendered.** The Load button and the table body carried **the same element id**, so every row was injected into the button. **Every Rust test passed, because the defect is entirely in the DOM.** Found by *looking at* the tab. **A view whose logic is exhaustively tested in Rust and whose output nobody has looked at is the exact shape that hides this** | ui 10(h) |
| 65 | Forwarding the bench's log over the bench's own link is a one-way flow → **it is a feedback loop, and at debug level it is self-sustaining.** Sending a line takes a mutex; the kernel traces mutex unlocks at debug; that record is forwarded, taking the mutex again. The capture came back as an unbroken alternation of the trace line and "records dropped". **Instrumentation that travels over the mechanism it instruments can amplify itself, and it only shows up at the verbosity nobody tests at** | bench 39 |
| 66 | A state-machine arm with no fallback should stay in its state, saving a pump loop from declaring a self-transition on every arm — asserted in the type's own doc comment → **staying put and re-entering are different, and a pump loop needs the one that re-enters**: no fallback consumes the frame and leaves the entry action un-re-run, so the request for the *next* chunk is never re-sent and the stall watchdog keeps counting from the original entry. **The design draft had written the self-transition explicitly, and the "simplification" was introduced while implementing, by reasoning about the type instead of about the protocol** | sd 60 |
| 67 | Pin a protocol manifest to a study by a CRC over its text, following the existing seal pattern → **the precedent had been reversed the day before (row 37), and another decision had independently ruled the mechanism out for the analogous case.** A saved study's pinned CRC goes stale on the author's next edit; and separately, **Core cannot read the firmware repo**, so a study naming a manifest renders on its author's machine and nowhere else. **A design grounded against a real firmware can still be stale against its own suite** | sd 58 |
| 68 | The protocol mechanism shipped — types, parser, validator, three seals, the action, 231 tests green and a cross-compiling staticlib → **the wire message had no protocols field, so nothing a study declared could reach the node that executes it.** The index pointed at something dev-bench had never been sent. **Every test passed, because every test was on one side of that hop.** **A message type is the one place a "this half is someone else's scope" split can hide a hole**, because the half you are not building is exactly the half whose input you never construct | sd 58, bench 41 |
| 69 | A protocol definition is 17,496 bytes, so two are ~35 KB against 71 KB free — measured, not estimated → **the measurement was real and measured the wrong thing, in both directions at once.** A firmware holds what the *interpreter* acts on, where every cross-reference is already an index: **the real C structure is 4,376 bytes, a quarter of the figure.** And the term nobody estimated dominates — staging buffers scale with the *wire* bound, and eleven count ceilings multiply to ~7.4 KB of manifest, mostly names the firmware discards. **A `size_of` on the sending side is not a bound on the receiving side, and a serialized worst case can exceed the value it serializes** | bench 41 |
| 70 | Row 60's buffer-sized-for-an-impossible-message was an inbound finding, fixed inbound → **the same defect sat in the outbound path the whole time, and this schema version was about to grow it.** ~6.6 KB staged for a message dev-bench cannot produce, heading for ~9.7 KB. **When a finding is "this bound covers a case that cannot happen here", the mirror-image bound is worth checking in the same pass** — there are usually exactly two, and fixing one makes the other harder to see | bench 41 |
| 71 | `doctor`'s schema check is a warn because the version "isn't available yet — neither side has one to compare" → **both sides have had one for a long time, and the check that exists to catch a version skew is a hardcoded string that never looks.** Meanwhile the live pair sat at Core wire v13 against a bench flashed to v14 — refused correctly and loudly, **but only to whoever typed the handshake endpoint by hand.** **A check stubbed out with its blocking reason written into the message ages into a check that asserts a falsehood**, and it reads as a known gap rather than a wrong answer, so nobody re-reads it | umb |
| 72 | A download pump loop counts received bytes against an announced total and leaves once it reaches it — proven through the reference interpreter → **that is the shape a download takes when no chunk is ever lost, and the first real firmware loses chunks by construction.** The DUT bursts four notifications per request into a bench that queues a protocol's notifications **four slots deep**; 275 were dropped in one five-minute window, and **a byte count that misses one chunk is short forever.** The real firmware already publishes the answer the count was reconstructing, on its low-rate status characteristic: **0 completed transfers became 34 of 34** | sd |
