## Which image the build describes

`embarch-atlas build` pins an atlas to one image's `edt.pickle` and `.config`. Under a multi-image sysbuild (application plus MCUboot) that is the application's, chosen by `domains.yaml` `default:`, else by the app directory's name, else the build fails naming the pickles it found. `build` and the Kconfig extraction choose through one function (`kconfig.image_dir`), so the two never describe different images. A build dir the caller names (`config --build`, `dt_node`) passes the app the atlas was built for, read from the atlas stamp, so it picks the same image `build` did. The detail is in the repo's `DESIGN.md`.

## Which families' pin use `join` decodes

`dt.json` holds devicetree pin use (pinctrl states, GPIO phandles, GPIO-routed interrupts) for two families: STM32 (`pinmux`, controllers `gpio[a-z]`, pins `PA4`) and Nordic nRF (`nordic,nrf-gpio` controllers by `port` or label digit, pinctrl `psels` through the `NRF_PSEL(fun, port, pin)` encoding with pull from `bias-*`, pins `P0.04`). `pin_decoder` records which; for any other family it is null, the pin map's DT column is empty, and `checks.md` says the pin-level checks had no input instead of listing them as run. On Nordic targets `dt-no-driver` folds the SoC infrastructure nodes nrfx drives without a Zephyr device (DPPIC, PPIB, MPC, UICR, GPIOTE) as expected.

## A target with no Zephyr board yet

A target may state `no_board = true` in `atlas.toml` when its PCB has no Zephyr board; a forgotten `board` still fails. `build` then writes an atlas pinned to the target and firmware commit whose stamp says there is no build and why, with no worktree and no west build, and `join` runs every step that reads no build artifact. `status` and `MAP.md` name each output that is absent for that reason (the build artifacts, `kconfig.json`, `dt.json`, `in_use.json`, `codecheck`, `limits`, the RM worklist, and the `config`, `dt_node`, `footprint` and `stacks` lookups, which answer that the target has no board yet) and each that is reduced (pin map, checks, MAP, graph, `register`, the second-look queue). A normal `build` supersedes it once the board exists. The rule and the per-output list are in the repo's `DESIGN.md` under principle 6 and "A target with no Zephyr board yet".
