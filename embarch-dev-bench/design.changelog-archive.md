- 2026-08-25 — **`CLAUDE.md`'s build rule narrowed to what it was actually for.** "Never build firmware or flash devices autonomously" had been applied to this repo's own firmware; the repo owner's intent was **DUT** firmware. Dev-bench is EmbArch's own test rig — a bad build here breaks the bench, not a customer's board — so builds and flashes proceed without asking. The DUT rule is stated separately and unchanged.
- 2026-08-25 — **Suite-wide design pass: decision 35, plus power profiling deferred.** Decision 35 replaces decision 21's static 16-slot `steps[]` array with one-step-at-a-time decoding from the retained span — ~9.2 KB of resident RAM back, the step ceiling gone, and `steps_crc` still verified before step 0 runs because the v9 `streams_crc` work already built the span walker. It also closes a divergence nobody had recorded: `DBM_MAX_STEPS_PER_STUDY` was 16 while the host's `MAX_STEPS_PER_STUDY` is 64, so a 20-step study passed every host check and was refused on the wire. Streaming steps from Core was considered and declined for two named costs (the seal can no longer be checked before execution, and per-step link latency corrupts authored timing) and kept with a trigger. Power-sampling hardware and the DUT connector are now deferred with Milestone 4 rather than individually open.
- 2026-08-25 — **Decision 29(a)'s firmware behavior implemented — Milestone 7 Phase B item 3, the last of the phase.** Taps are decoded and stored (`pc_read_stream_tap`, a 12-byte `dbm_stream_tap` that keeps `id`/source/scope and deliberately not `name`/`encoding`), opened and closed from their declared `StreamScope` as steps advance, and the GATT transcript now rides `StreamChunkBatch` on its declared tap. **Tag 10 is gone from the encoder and from `main.c`; its value stays burned rather than reused, because the "never flashed" argument that licensed reusing tags 2/3/4 is spent the moment this firmware is flashed.** 34/34 ztests on `native_sim` (was 33), both `native_sim` and `esp32c5` build. **Two corrections this pass forced, both recorded in decision 29(a) itself rather than fixed silently:** the four payload-interpretation deletions this item was scoped around **were already gone** — Phase A took them, so the item was purely additive and the net-negative-size expectation could not be met (`sram0_0_seg` +128 bytes); and the reserved `dev-bench` log tap **needed a Core change**, since `tap_for` resolved ids against the submitted `Study` and would have dropped every record from a tap dev-bench invented. It ships as Core synthesizing the tap and rendering the `LogLine` frames it already gets, which is less firmware for the same closed asymmetry.
- 2026-08-25 — **Schema v9's wire contract implemented** (Milestone 7 Phase B item 0; decision 29's own entry has the detail). `Step.power_sample` dropped from encoder and decoder; `StudyStart`'s new `streams_crc` walked and checked via a new `pc_skip_stream_tap`, with `main.c` aborting the study on a mismatch; `study_ffi_stub.c`'s schema constant corrected from a stale v4 to v9. **Two things this pass found rather than implemented:** the C decoder never walked the `streams` span, so the second seal cost a full tap walker and the firmware grew **+654 bytes** instead of shrinking; and `StepResult` was still writing two bytes for fields retired at v8, invisible because it had never been pinned across the two languages — both fixed, and `StepResult` plus a three-tap `StudyStart` are now pinned. 31/31 ztests pass on `native_sim` (was 28) and the app still builds there. - 2026-08-04 — `ble_bridge_real.c` went from one wired-up action to the full `Action`/`GattOperation` surface (§3 decision 16's implementation note). `BleConnect` covers both roles: central scans (filtering on `target_address` when set, ignoring non-connectable advertisers) and initiates from the scan callback; peripheral advertises and, when a specific `target_address` was asked for, drops a wrong peer and keeps advertising for whatever of the step's budget remains rather than reporting a Pass against the wrong DUT. `DataExchange` acts as a GATT client: primary-service then characteristic discovery (cached per connection, invalidated on disconnect), then read / write-with-response / notify / indicate / subscribe / stream-capture. Every action is bounded by one deadline derived from `Step.timeout_ms` — discovery included, not just the final request — with `Notify`/`Indicate` additionally bounded by the `GattOperation`'s own timeout, whichever expires first. A timeout cancels the pending GATT request (`bt_gatt_cancel`) instead of leaving Zephyr owning the params struct, which would fail the next step with `-EBUSY`. `BleAdvertise` was rewritten in the same pass, partly as a bug fix: it used `BT_LE_ADV_CONN_NAME`, which no longer exists in Zephyr 4.x, so the `nordic` workspace could not have compiled; it now builds real advertising data from the Action's own `local_name` and `adv_interval_ms` (previously ignored in favor of `CONFIG_BT_DEVICE_NAME`) and puts service UUIDs in the scan response, failing explicitly if more are requested than a legacy scan response can carry (exactly one 128-bit UUID) rather than silently advertising a subset a DUT would then never find. Requires two new Kconfig symbols in `app/boards/nrf54l15dk_nrf54l15_cpuapp.conf` (`CONFIG_BT_GATT_CLIENT`, `CONFIG_BT_GATT_AUTO_DISCOVER_CCC`) plus a larger `CONFIG_MAIN_STACK_SIZE`, since actions now block on the main thread. Deliberately *not* added: an explicit `bt_conn_set_security()` call — Zephyr's ATT layer already re-runs a request at higher security when a DUT answers with an authentication/encryption error, which is all decision 11's Just Works pairing needs. Verified on `native_sim` (which builds the stub, kept in signature-sync by hand): `west build -b native_sim app` and the 8-case `app/tests/serial_protocol` ztest suite both pass, and feeding a COBS-framed `Hello` in via `-uart_stdinout` still produces the full `HelloAck`(schema 2, `compatible`, `firmware_version`)/`LogLine`/`StreamStart`/`StreamChunk`×3/`StreamEnd`/`LogLine` sequence — so the header changes didn't disturb the serial path.
