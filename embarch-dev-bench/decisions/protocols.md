# embarch-dev-bench decisions: Running an `.eap` protocol

**Status:** active, 2026-09-02.

The state-machine interpreter that made `Action::RunProtocol` executable rather than only expressible.

Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 41 — The bench runs a `.eap` state machine, and the manifest crosses the wire to get here
Until this pass **nothing had ever executed a `.eap` file except the crate's own host-side reference interpreter**: the mechanism was real, tested, sealed, and end to end unrunnable.

**The first thing this pass found is that the wire did not carry it.** The upstream decisions shipped the study field, its seal, the action and the result field, and stopped one field short — `StudyStart` had no `protocols` at all, so the action named an index into something this node had never been sent. The two fields are **appended at the end**, not inserted beside the existing seal: postcard is positional and this protocol's rule is that a new field goes on the end. The structural rule that each seal immediately follows the span it covers is a property of the *pair*, satisfied either way.

**The interpreter takes events and returns instructions, and has no radio in it.** No Zephyr, no BLE, no clock: a caller feeds it arrivals and timer expiries and reads back the writes it wants performed. That is what makes the semantics testable — the ztest suite drives the **real worked download**, decoded out of the pinned frame Core would send, through the same sequences the Rust reference is driven through. Chief among them the one that is easy to get wrong because it already was once: an event arm with no `otherwise` consumes the frame and stays put *without re-entering*, while `otherwise: goto <this state>` re-enters, re-sends the flow-control ack and restarts the stall watchdog. A pump loop needs the second, and both are pinned.

**Names are dropped, all but the one reported back.** Every cross-reference inside a resolved protocol is already an index, so this firmware compares no strings. The decoder still *walks* every discarded name, because postcard carries no per-field length.

**`struct eap_operand` is packed, and that one attribute is worth ~12 KB.** Its literal is an `int64_t`, and an operand is the most-multiplied thing in a manifest — two per condition, two per expression, one per write field, times arms, times states, times protocols, times two static message structs. Naturally aligned it is 16 bytes, **six of them padding**; packed it is 10. The cost is byte-wise loads on a target without misaligned access, on a path that runs once per notification.

**One count cap below the crate's, and one cap that is not a count.** Every ceiling matches the crate except the per-state event-arm count, which is 2 against the crate's 4: an arm is the heaviest thing a state holds and is multiplied by states, protocols and both statics, and **both worked protocols use one arm per state.** Refused by name at decode, never truncated — sharper than the step cap, because a state machine missing a transition still runs, and branches wrongly while looking correct. The cap that is not a count is a **byte cap over the whole span**, because the eleven count ceilings multiply into a wire bound nothing would ever send: at those ceilings one protocol can *encode* to ~7.4 KB, almost all of it names this firmware discards, against a real worked protocol whose entire `StudyStart` is 398 bytes. **A byte cap says the true thing where a product of eleven ceilings says a false one.**

**A third instance of the same over-sized-buffer finding, in the other direction:** the TX staging buffer was sized by the *general* bound — which is `StudyStart`'s — for a message dev-bench cannot produce, since Core is the only sender of one. Now sized by the result message's bound, shrinking it from 9,270 to 3,082 bytes. Scoped to the *application's* buffer, because the round-trip tests encode a `StudyStart` through the general one and narrowing that would trade a real test for RAM.

**The measured cost, which the crate's doc had recorded as unmeasured:** SRAM went **81.12% → 87.04%**, +22,400 bytes. Where it went, by symbol: the two static message structs +17,536 together (the storage), the raw staging buffers +9,253 (the wire bound), against −6,188 from the TX buffer above. **The design pass estimated 17,496 bytes for a protocol definition; the real C structure is 4,376** — the wire bound rather than the storage turned out to be the dominant term.

**What a run does on the bench:** wildcard discovery, then each declared source resolved against the DUT's real GATT table — a source the DUT does not have **fails the step naming it**, decision 40's rule for a named target rather than the unfiltered walk's log-and-skip. Every source at least one frame reads from gets subscribed; **a source only ever written to deliberately does not**, because subscribing to it would be this bridge deciding something the manifest did not say. Then the loop: perform the write the interpreter asks for, wait on a small queue for whichever comes first of a frame, the state's deadline or the step's, and feed it back. **A dropped notification is counted and reported**, because a run that missed a frame reached the wrong state. Subscriptions are torn down unconditionally at the end: a protocol run is scoped to one step by construction, unlike a monitor *window*. **An acknowledged write is waited for and still never triggers a transition** — on the DUT this was designed against, a control-point write's response confirms only acceptance, and the authoritative answer arrives later on a different characteristic.

**The stub reports no protocol at all**, the third time it refuses to manufacture a claim: a run on `native_sim` runs no machine, so there is no state it stopped in, and reporting none reads as the truth.
