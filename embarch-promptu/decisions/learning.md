### 14 — A weekly ✓/✕ sheet, drafted locally
A systemd user timer runs a stripped Opus `claude -p` every Wednesday at 08:00 (`Persistent=true`), about $1.5–3 a week [assumed]. Its inputs: friction in sessions, his edits, skipped and overridden questions, prompts no pattern matched, outcomes, and a quarterly or new-model refresh of published practice. **Every event becomes a proposal**; a specific fact becomes a memory entry, so patterns stay generic. He approves the sheet in a Promptu section of the Desk tab, the spot `embarch-desk` decision 65 kept, hidden while it has nothing open. **The weekly pass shows in two places**: the Desk section, and the chat's Promptu card (owner, 2026-11-07), which reads the next run and a missed run from `promptu week status` and the open count from `promptu desk` (contract §9, §14.4). No Slack message, since the desk's Slack connector is gone (`embarch-desk` decision 66). **Contract, EMB-272:** the timer is generated by `promptu week timer` from a config key (45), one sheet waits at a time (46), and every pack event ends in a proposal that names a question, a new question, the template, the picker, a memory entry or a new pattern; a specific, stable fact is a memory entry, never a pattern (contract §10, §14.3). **Rejected:** 👍/👎 clicks and memory corrections as inputs, cloud routines (the data stays local), the fleet, a session cron (it skips while the session is busy). *Amended by 42: his edits are compared against the rewrite, the log's `rendered`.*

### 30 — The weekly sheet works without the Desk
Decided by the owner on 2026-10-29; specified in contract §14 (EMB-272); `week mark` and `week apply` built (EMB-279, 2026-11-23). Without the Desk, the weekly ✓/✕ sheet is `week/<week>/sheet.md`, a view of `sheet.json`; marks go through `promptu week mark`, `promptu week apply` applies them, and a `/promptu:review` skill walks it in the terminal. Writing a ✕ in the file's box, or a note under a line, is read back by `mark` and `apply` ([forks](../../../embarch-promptu/docs/forks.md) W5, answered provisionally in EMB-279: a ✕ cuts, a ✓ never approves). With the Desk present, its Promptu section shows the same sheet (14). **Rejected:** a sheet only the Desk can show.

### 15 — Success after four weeks
Reported on each sheet as `numbers` (contract §10, §14.5; the first cut computes `fills_kept`, `patterns_kept` and `questions_per_run` from footers, and the friction numbers from the pack's candidate redirects, W2): corrections per prompt at or below 0.10 against non-Promptu sessions as a control, redirected messages per task start down about 30%, at least 90% of pre-filled answers kept, at least 85% of picked patterns kept, questions per run falling, and a one-key "better · same · worse" line.

### 43 — An approved pattern change lands as a commit on a branch, never pushed
Decided by the owner on 2026-11-23, for build step 4; built in EMB-279 (one commit per changed pattern, carrying all of that pattern's approved lines; the checkout's own branch is checked out again afterwards, forks W17). `promptu week apply` commits each approved pattern line on a branch in a checkout named in Promptu's config, with the version bumped, lint clean, the example renders updated, and a configured public-safety command run first (for the owner, the suite's client-name and denylist checks). Nothing is pushed: landing and reinstalling stay the owner's. With no checkout configured, the pattern lines are written out as a patch. **Rejected:** committing to `main` and pushing, which breaks the branch-and-land rule; applying memory lines only, which leaves nothing learnt reaching a pattern.

### 44 — A run is a log entry, and its sent prompt is matched by footer, project and time
Decided by the owner on 2026-11-23, for build step 4. The run list is `log/`. A run's sent message is the first owner message after the log time, in that project, carrying the same footer line; a tie goes to the text closest to `rendered`. A terminal run's edit is read from its draft, kept until the week is packed. **Rejected:** a `run=` footer field, which puts an id in every prompt; transcripts only, which miss every terminal run. Heuristic on two identical quick runs, and said so.

### 45 — The schedule lives in Promptu's config
Decided by the owner on 2026-11-23, for build step 4 and EMB-85. The weekly schedule is a config key (default Wednesday 08:00); `promptu week timer` writes the systemd user units from it, and `promptu week status` computes the next run and a missed one from it and the last run record, so the chat asks Promptu and never the scheduler. Amends 14's timer to be generated rather than hand-written. **Rejected:** asking systemd, Linux-only; reporting the last run only, which cannot say "missed".

### 46 — One sheet waits at a time
Decided by the owner on 2026-11-23, for build step 4. A new week's run re-proposes the open lines' events with the new week's and marks the earlier sheet superseded. **Rejected:** sheets piling up; skipping a week while a sheet is open, which loses events past the transcripts' 30 days.

### 47 — Step 4's first cut: re-render and replay, a commit as the only outcome
Decided by the owner on 2026-11-23. Step 4 tests a proposed pattern by re-rendering its examples and replaying 3 to 5 real past prompts, and counts a commit as the only outcome, read from the session's and its subagents' transcripts, not `git log` (forks W16). 14's quarterly or new-model refresh, and outcomes beyond a commit (a PR merged, a study passed), come later, each its own issue. The smaller step 4 choices run on their recommended defaults and are recorded in the repo's `docs/forks.md` by the contract unit.
