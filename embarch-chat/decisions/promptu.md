# embarch-chat decisions: Promptu in the chat

**Status:** active, 2026-10-30.

How the chat draws `embarch-promptu` (its build step 3): the icon and its card, the pass and its dialog at a task start and on desk Start work, and the Memory menu. Promptu itself — the CLI, the patterns, the footer — is [`embarch-promptu`](../../embarch-promptu/spec.md)'s; the chat runs its `promptu` CLI and draws what it prints. The rail that holds them is decision 94 ([shape.md](shape.md)); the 💡's split with Promptu is 97 ([assistant.md](assistant.md)).

Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 95 — Promptu's icon is an indicator; hovering it opens its card

Decided by the owner, 2026-10-30. **The Promptu icon (✨) in the rail lights when the next Enter will run the pass**: Promptu on and its binary found, at a task start — the chat's first prompt, or the Start work chat — and never for a reply inside a running task, a `/command`, a side question, or a draft whose last line is already a `— promptu` footer. It is not a switch. **Hovering it opens a card that holds four things:** Promptu on or off; one line on what it does; the pattern for the next prompt — auto, or one of `promptu patterns`, which lights the icon for that one prompt, a reply's too; and Quick mode — no dialog, every recommendation taken, the prompt still put in the draft to check. The switches are the extension's own state for every window, never the owner's settings (82's rule): on, and Quick mode off, by default. There is no key for the pass. The binary is `embarchChat.promptuPath`, `promptu` on PATH by default. The forced pattern mid-task, the switches' home and no key are the owner's picks (`embarch-promptu` decision 35). Its name says whether the next Enter runs it ("Promptu — runs on next Enter"), never a pressed state; opened by the keys, the card takes the focus and the pointer leaving keeps it, a hover never takes it from the draft, and Esc closes it. **Rejected:** the icon as the switch; anything else on the card for now (this week's sheet waits for build step 4); a key for the pass on any draft.

### 96 — At a task start, Enter runs the pass in a dialog over the chat, and the prompt lands in the draft, unsent

Decided by the owner, 2026-10-30 (`embarch-promptu` decisions 9, 12, 16; SYNTHESIS §2, §5.2). **With the icon lit, Enter does not send.** The host runs `promptu prep` in the chat's folder with `--have` for the EmbArch parts present (`desk` while the desk answers; `embarch-api` when the chat's CLI lists it, or before it starts when its binary is on PATH — `embarch-promptu` decision 36), `--desk <file>` when the chat has a work item — its brief from the desk's `GET /items/{id}/brief`, read by the host so the token never reaches a page (20), cut to 2,000 characters as the terminal skill cuts it, in a private file removed once `prep` is done — the forced pattern, and Quick mode as `--rec`. **The dialog is a modal over the chat**, drawn from `prep`'s pages with no model call, one page at a time as `promptu next` plans them: each question's recommended option picked, Other for free text, the chip row first when the pick is weak, what the sources already answered behind a fold. Enter answers the page; **Accept all recommendations** (Ctrl+Enter) renders with `--rest recommended`; **Esc** renders with `--rest assume`, the answers given and those touched on the page kept, the rest stated assumptions (the owner's pick, `embarch-promptu` decision 38). **A pre-filled answer is changed in place**: Change opens its options, and the pick goes as an answer to its id, `!` in the footer (decision 38). The dialog is modal — `aria-modal`, Tab kept inside, the chat behind inert (Quick mode's pass too, with a line saying so), a click on the backdrop keeping Esc and Enter — and opens on the option picked already. The host holds the run, so a hidden or reloaded page shows the same dialog. **The prompt replaces the draft and is not sent**: Ctrl+Z puts the owner's back, and the next Enter sends it, after the linker's cards (88). **Promptu never blocks sending**: not installed, a non-zero exit or a timeout is one line under the input and the draft as typed; Esc while it reads the prompt skips it (in Quick mode, Esc wherever the focus is); a task start has one pass, so the next Enter sends, and the draft takes the focus back however the run ended. A run goes with its chat: an idle close waits while its dialog or its prompt is the owner's (41's "waits on the owner"), and a process that closes or a view dropped forgets it. **Desk Start work** (reverses 11): the pass runs on `Work on KEY — title` with `--start` (`embarch-promptu` decision 32) as the chat opens, its dialog over the empty chat; when the pass fails or is skipped, the desk's old starter is sent, as 11 sent it, and one line says so; with Promptu off or not installed, it waits in the draft, unsent (the owner's picks, `embarch-promptu` decision 34). **Rejected:** a model call in the dialog (the pass is `prep`'s, once); the prompt sent by itself; a page form for every question at once (the terminal pages, and `next` re-plans after each answer); a send blocked by a pass that failed.

### 98 — The Memory menu, v1: scope, then domain, then kind; view and open to edit

Decided by the owner, 2026-10-29 (`embarch-promptu` decisions 8 and 16; SYNTHESIS §9.8). **The rail's Memory entry (🧠) opens `promptu memory --json` for the chat's folder**, read again each time it opens: the scopes User, Auto memory and Project; in auto memory each `## ` domain, then each kind in its order (preference, rule, trap, reference, status); each entry with its age, its stale flags in words, and **where it was used** — how often a footer of the last 30 days pre-filled a question from it, each pattern, question and date on hover (contract §5's `used`), the global `CLAUDE.md`'s on the User line. A `CLAUDE.md` is one row per section. **A click opens the entry's file beside the chat** (92), a dead link its index line — and only a file the menu was given, never a path the page names. "Where it's used" counts prompts the owner sent only (`embarch-promptu` decision 33). Opened by the keys, the menu takes the focus; Esc closes it, the focus back on its entry. **Rejected for v1:** editing in place; startup cost (decided out).
