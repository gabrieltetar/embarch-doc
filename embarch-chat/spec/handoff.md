# embarch-chat spec: the handoff

**Status:** active, 2026-11-17.

Split verbatim from [../spec.md](../spec.md) §2 on 2026-11-17, under [DOC-COMPACTION.md](../../DOC-COMPACTION.md) §2: `spec.md` was in reserve. The bullet is unchanged. Current truth: [../spec.md](../spec.md). Why: [../decisions.md](../decisions.md).

- **An agent can hand its chat to a fresh session** (103): `handoff(prompt)`, a tool of the panel's own MCP server, shows a card with the prompt editable and Continue or Stay (`embarchChat.handoff`: `card`, `immediate`, `off`). Continue starts a new session on the same work item in the same panel, in the chat's mode, model and effort, the old history above a divider; Stay answers the tool and the agent carries on.
- **A session that died without a handoff can be read back**, read-only (EMB-189): `last_session`, a second tool of the same MCP server (`cwd` default the chat's folder, `turns` default 6), and `node dist/last-session.js [--cwd] [--turns] [--config-dir]` over one function, `src/lastSession.ts`. It reads **the chat's own login's** `projects/` folder (101: `Chat.projectsRoot`, the `configDir` login's if the chat has one, passed through `HandoffPort`), never the extension host's; the CLI takes `--config-dir`, else the environment's login. It takes the newest `*.jsonl` of the cwd's own `projects/<encoded cwd>/` folder, else of its main clone's (`git rev-parse --git-common-dir`), and prints the last N user and assistant text turns with each tool call as its name plus the first 300 characters of its input, oldest first, then background shells, Monitors and agents it started and never saw a finished `<task-notification>` for. **Never the caller's own session:** by id when the chat has it (the tool always does), and otherwise a file written within the last 30 s is skipped as live, so a session that died under 30 s ago is missed from the CLI. Nothing is stored or written.
