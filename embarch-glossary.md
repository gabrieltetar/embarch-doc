# embarch: glossary

**Status:** active, 2026-09-02.

The load-bearing terms used across every doc in this repo. **This doc restates no design — it links to the doc that owns each term.**

**Deliberately no version numbers or constant values here.** A derived value recorded away from the work that derives it is a fact with a shelf life ([reversals](embarch-decision-reversals.md) row 18), and this page went stale on exactly that twice.

| Term | Meaning | Owning doc |
|---|---|---|
| **DUT** | Device Under Test — the physical firmware and hardware being flashed, reset or bench-tested. **Distinct from dev-bench, which tests it** | [core](embarch-core/spec.md) |
| **Core** | `embarch-core`, the OS-level service owning the debug probe and serial console — **the lowest layer, and the only one that touches hardware** | [core](embarch-core/spec.md) |
| **dev-bench** | `embarch-dev-bench`, the physical rig **playing the DUT's BLE counterpart** and sampling power during a study | [dev-bench](embarch-dev-bench/spec.md) |
| **suite** | The whole `embarch-*` set of sub-projects together | [embarch.md](embarch.md) |
| **project** | A named, configured build target in the API's config — **one repo's buildable thing, with how to build it** | [api config](embarch-api/interfaces/config.md) |
| **target** | One concrete buildable (board, soc, cpucluster, variant, revision, app) combination within a discovery project, **validated against the files a build actually needs rather than what a board file declares** | [api](embarch-api/decisions.md) decision 12 |
| **discovery kind** | `static` — a hand-authored project entry — or `zephyr-west`, where **every target is scanned live on each call and nothing is written down** | [api](embarch-api/decisions.md) decision 12 |
| **board qualifier** | Zephyr's own naming grammar for a buildable target: `<board>@<revision>/<soc>/<cpucluster>/<variant>` | [zephyr](embarch-zephyr.md) |
| **chip** | An opaque probe-rs target name — **a different namespace from a Zephyr board, with no mechanical mapping, which is why nothing guesses it** | [core](embarch-core/spec.md) |
| **probe** | A physical debug probe probe-rs can attach to. **Declared as belonging to a role by a human, because no software can derive which board a probe is wired to** | [topology](embarch-topology/spec.md) |
| **hw_lock** | Core's single mutex serializing **all** DUT probe and serial access. **A second process calling a hardware function directly, without sharing it, is a real class of bug** | [core](embarch-core/decisions.md) decision 4 |
| **topology class** | `local` / `wsl-host` / `remote` — the three ways the API and Core can be arranged relative to each other. **Detected live on every call; only the class is ever persisted, never an address** | [topology](embarch-topology/spec.md) |
| **Study** | A scripted sequence of BLE stimulus and interaction steps plus measurement, run against a DUT through dev-bench. **Entirely static once submitted** | [study-designer](embarch-study-designer/spec.md) |
| **Step** | One action within a study, with a timeout, an optional pre-delay the bench sleeps *before* running it, and a continue-on-fail rule | [study types](embarch-study-designer/interfaces/types.md) |
| **study seal** | Any of a study's **three** CRC-32s — over `steps`, over `streams`, over `protocols` — **each covering one contiguous span, each recomputed and overwritten by whoever submits, each checked independently at both hops so a mismatch says *which* part is corrupt.** Siblings rather than one widened seal, because a seal sits between the spans on the wire | [study-designer](embarch-study-designer/decisions/versioning.md) |
| **wire schema version / host type version** | Two hand-bumped constants, **one per hop they guard**: the Core↔dev-bench handshake, and the API↔Core status check. **The host one is a strict superset** — a study crosses that hop whole, including fields dev-bench never sees — so it moves for host-only changes too. **Both are mismatch *detectors*, never negotiators**, and a compile-time assertion holds the host one at or above the wire one | [study-designer](embarch-study-designer/decisions/versioning.md) |
| **version gate** | A study's refusal to run against firmware that is not the build it declares — **checked before any step runs**, naming both strings. `"any"` is a legal, explicit answer | [study-designer](embarch-study-designer/decisions/versioning.md) decision 40 |
| **provenance** (study) | What a result actually ran against: the bench and DUT firmware versions **and how each was established** — reported by the bench, flashed this run, or merely declared. **An unverified assertion must not look identical to a verified reading** | [study-designer](embarch-study-designer/decisions/versioning.md) decision 40 |
| **stream tap** | One declared capture in a study: **where bytes come from, how long the tap lives, and how to render what arrives** — all declared parameters, so there is one pipeline rather than one per kind of data | [taps](embarch-study-designer/interfaces/taps.md) |
| **raw before decode** | Core's rule for every tap: **the bytes that arrived are written byte-for-byte first, and only then decoded.** A decode that fails costs the rendering, never the capture | [core](embarch-core/decisions.md) decision 30 |
| **signal link** | A named signal originating at the DUT — an outpost UART, a console UART, an SWO pin — **with a declared route.** A study names the *signal*, never the carrier | [topology](embarch-topology/decisions/links.md) decision 18 |
| **dev-bench bypass** | A signal link routed `Direct`: **straight to a serial port on the Core machine, skipping the bench.** Modelled as a first-class route rather than "the temporary way it happens to be wired", so **moving it later is one field and no saved study is rewritten** | [topology](embarch-topology/decisions/links.md) decision 18 |
| **outpost** | `embarch-outpost` — a Zephyr module an engineer compiles into the **DUT's own** debug firmware, emitting a thread/ISR/marker timeline out a TX-only UART | [outpost](embarch-outpost/spec.md) |
| **frame** (outpost) | The unit of the outpost wire: a COBS-delimited batch of records, carrying its own CRC and **Core's arrival stamp**. That stamp is the clock that *places* a trace against every other stream; the DUT's own per-record counter is the one that *measures* | [outpost wire](embarch-outpost/interfaces/wire.md) |
| **manifest** (outpost) | The build artifact mapping a trace's opaque IDs to names — markers, thread addresses, ISR vectors — **generated from the linked image, so no CRC of it exists at compile time.** Matched by build ID, and **a mismatch costs the *names*, never the capture** | [outpost](embarch-outpost/decisions/manifest.md) |
| **`.eap` / protocol manifest** | "EmbArch Protocol" — a small purpose-built text grammar, **authored by an engineer in the *firmware* repo**, describing a DUT's own protocol as a state machine so the suite executes it instead of guessing it | [protocols](embarch-study-designer/decisions/protocols.md) |
| **`RunProtocol`** | The action that **hands the BLE link to an `.eap` state machine for the length of one step** | [protocols](embarch-study-designer/decisions/protocols.md) |
| **guard-reachable** | The half of the `.eap` grammar that **crosses the wire to dev-bench, because a running state machine has to evaluate it in real time.** The rest stays host-side | [protocols](embarch-study-designer/decisions/protocols.md) |
| **dev-bench log level** | How verbose the bench's own firmware is **for one study** — applied on dispatch and reverted afterwards. **Runtime filtering can only reduce below what the build compiled in**, so the Kconfig that looks like a default is really a ceiling | [dev-bench](embarch-dev-bench/decisions/logging.md) decision 39 |
| **dev-bench debug log** | Every log line the bench sends, in a file beside Core's own — **so debugging a study after the fact does not mean correlating two files by timestamp** | [core](embarch-core/decisions.md) decision 37 |
