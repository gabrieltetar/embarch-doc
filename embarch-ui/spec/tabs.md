# embarch-ui: the six tabs

**Status:** active, 2026-09-29.

Split verbatim from [../spec.md](../spec.md) (`tasks/ui/069`), when decision 44's roles/topology growth put that file back over its cap. Nothing below is reworded from the version that moved, except the opening paragraph, which carries the newer wording from `spec.md` (desk, not project; `tasks/ui/089`). What each tab does. Current truth: [../spec.md](../spec.md).

One persistent left sidebar, one top status bar, client-side navigation by URL fragment (`#topology`, `#live-study`). **The open desk is shell furniture, at the foot of the sidebar** (46, 57): one desk — and so one firmware repo — at a time, or a bare repo with no desk, named on every tab and changed from a dialog the Study Designer's own card also opens. A fragment names a tab, and may name what it shows — `#desk?item=`, `#live-study?study=`, `#topology?board=` mark it, then leave the address (58). **A retired fragment resolves to the tab that absorbed it**, never to the last one that browser had open: `#enroll` is `#topology` (43), `#dashboard` is `#desk` (56). What each tab does: the table below.

| Tab | What it does |
|---|---|
| **Desk** | The work cockpit (56): one card per [`embarch-desk`](../../embarch-desk/spec.md) work item — issue status, PRs, sessions (one line each: Open chat for an `embarch-chat` chat, else Jump), notes, bench activity, *Open in VS Code* — for the open desk only, each with a chip per waiting day; **the hand** at the head of the tab, every desk's waiting tiles as a row of cards with ✓ to Harvest or ✕ ([`embarch-desk` decision 57](../../embarch-desk/decisions/cockpit.md)), the tile dialog offering *Fold into <day>* (58); a tile sent while its sessions ran on comes back as a dashed **+** card adding to the same entry ([`embarch-desk` decision 64](../../embarch-desk/decisions/desks.md)); its hours go only when typed (59); no Slack bar since 2026-10-29, its spot left empty for a Promptu section ([`embarch-desk` decision 65](../../embarch-desk/decisions/cockpit.md)); **Today's work** under the cards — a day list across every desk with links out, what was done, status and sessions; the desk form (57); the Connectors panel holds the chat setting. Reaches the desk only through this server: `/api/desk/{*rest}` and the SSE `/api/desk-events` |
| **Topology** | **The bench canvas, full screen with no page scroll** (78; [bench.md](bench.md)): the saved bench picked in the top bar drawn as the hardware (76) and edited there ([bench-editing.md](bench-editing.md), 80–87) — parts by look, only wired connectors until a part is hovered or selected, this machine a hub, cables solid to it and dashed per config, config tabs along the bottom, a floating inspector, pan, wheel zoom and Fit — with a glow on each bound probe or port Core enumerates now and Validate's verdicts under the parts (77). The bar holds the picker (with *New bench…*), the bench's path, **+ Part** (the parts bin, a drawer down the canvas's left), undo, redo, *unsaved changes*, **Save** (Ctrl/⌘+S), **Validate topology** and four panels over the canvas: **Signals** (the one human surface for declaring a wire, 10), **Board types** (the project's catalog, each row its revisions and variants, 47), **Saved benches** (save, load, delete; 44) and **Old diagram**, the two role boxes a probe is dropped on (43; an enrol that moved a role names it, 61) and whose board type is clicked to pick as one real scanned combination (45, 47), until the editor replaces it. Validate's report opens as a fifth, and once a pass has run a **Report** button reopens it without a new pass — it holds the only control that clears a leftover role. **Checks** opens the rule checks' findings, its button counting the errors and warnings. Under the canvas, the **tray**: what is plugged in and on no part. One panel at a time, scrolling inside itself, closed by its button and a press outside. **Esc closes the topmost thing**: Core's prompt owns it, then the bench editor's dialog (drawn over the part editor), the part editor's own question, a Topology dialog — the part editor included — over a panel, the panel, a cable being laid, a picked tray chip, then the parts bin; **it never clears a selection**. Opening a panel moves focus to its first control, closing it returns focus to the button that opened it. `#topology?board=` and the desk banner's *Review it on Topology* open the panel holding what they name (Saved benches, for the apply report); a save or delete there keeps the canvas's zoom, config and selection while the same bench is still listed |
| **Study Designer** | **Authoring and saving** a study; running it is Live Study's (31). Four panels (41): **project**, whose only field is the repo path (51), with the **Static firmware analysis** submenu that runs the GATT extractor — one ships, so there is a button and nothing to configure; the **study toolbar**, whose **Build options…** dialog holds the two `requires` fields, the dev-bench log level and the **Build card**; **steps**; and **Define the wire** — taps, `.eap` manifests and editor, the action registry, layouts. The Build card (38): app, an **ordered** snippet list, west flags and a three-state outpost mode per header flag — off by default, unavailable-with-a-reason off a configured project |
| **Live Study** | Runs a saved study and watches it land, or opens a past one and reads it back. Stacked cards: run/open with the studies list, the **build card** where this run builds its own firmware, status, steps filling in live, the event feed, one console per `Text` tap, the **Time chart** (every stream on one axis), the trace chart, and one data card per tap. **A host study's operator prompt opens a modal on whichever tab is open** (69): text, countdown, Confirm/Cancel, a sound and a notification, closed by whoever answers first |
| **Atlas** | The open project's hardware atlas as one map (52): modules, MCU peripherals and pins, and every part on every board as a generic schematic symbol, each pin labelled with its net and the firmware's name for it (53). Picks an atlas, walks the problems, opens each claim's source down to the page or the code line (54). Read-only |
| **Debug** | Three sources: two live tails — Core and `embarch-api`'s rolling file, both reaching the browser as this UI's own `lines` SSE event — and **builds**, stored rather than tailed: every firmware build this UI ran, picked from a list (39) |
