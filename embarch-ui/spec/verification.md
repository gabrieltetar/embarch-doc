# embarch-ui: verification technique

**Status:** active, 2026-10-26.

Split verbatim from [../spec.md](../spec.md) (`tasks/ui/078`); the bench drives were added on 2026-11-01, the live drive on 2026-11-02.

**"Tested in Rust, never looked at" is how this UI's worst defects hid**, so `tests/browser/` is the one to reach for: a headless-Firefox harness driving the **running binary** through geckodriver against a stub embarch-core. The assets are `include_str!`-embedded, so the deployed artifact is the only thing that can be checked, and a state a bench will not produce on demand is testable. `drive.py` covers Live Study, `drive_build.py` the Build card and builds source, `drive_topology.py` what the old diagram did, now on the canvas, and the panels, `drive_bench.py` the bench canvas, `drive_bench_edit.py` editing on it, `drive_bench_parts.py` the part editor, `drive_bench_live.py` making a bench live, `drive_links.py` a link marking what it names, `drive_fonts.py` every page; `tests/browser/README.md` has the shape. **`drive_bench.py` puts a proxy in front of the real binary** that answers `/api/bench/*` from fixtures and passes everything else through, so the canvas glows from the binary's own snapshot of the stub Core; its built-in catalog is generated from the build and a `cargo test` fails when it drifts (79). **The two editing drives run the real bench routes over a scratch repo instead** (89): `drive_bench_edit.py` reads the TOML on disk after every Save and holds a `PUT` in its proxy to test a save in flight, and `drive_bench_parts.py` compares every refusal the dialog shows with the same request made outside the browser. **`drive_bench_live.py` stubs the live routes in its proxy** to reach the states and races a real apply will not produce on demand, and `EMBARCH_LIVE_REAL=1` passes them to the binary over a stub Core recording each write (95). **`tests/element_ids.rs`** (24) is the static half, catching the one shape a text scan can: no id declared twice, no id lookup dangling.
