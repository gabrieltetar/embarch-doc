# embarch-ui: open

**Status:** active, 2026-09-04.

Unresolved only. Current truth: [spec.md](spec.md). Why: [decisions.md](decisions.md).

- **Where the reflash selector should live is genuinely undecided.** `run_study --reflash` is `embarch-api` orchestration — it sequences check → build → flash → submit and owns the project config and build machinery — while `embarch-ui` posts studies straight to Core and builds nothing. Three shapes: duplicate that orchestration here, give `embarch-ui` a dependency on `embarch-api` (a direction the suite has nowhere), or leave reflash terminal-only. Settled as the third for now, **and the run dialog says so** — but "the UI cannot reflash" is a limitation rather than a design goal. The mismatch override and the before-the-run mismatch display are built and unaffected. Decision 11.

- **Nothing has compared a trace's placement against a second stream in the same study.** The DUT clock measures; the host's *places*, at an observed 4.0 ms median placement resolution on the reference capture. Whether the two actually line up against, say, a power capture is the check the dual-clock flag exists to enable, **and it has not been run.** Every outpost wire constant is still an unmeasured default with the instrumentation's own overhead deliberately uncharacterised, so a working view is not validation of the numbers underneath it.

- **The 250,000-row cap is kept, now against a real measurement at the next number up instead of an extrapolation.** `trace::scratch_view::synth_capture` builds a capture of the committed fixture's shape entirely in memory (no file on disk), and the `#[ignore]`d `measure_the_row_cap_at_scale` decodes it at 250k / 500k / 1M rows: decode time **257 ms → 604 ms → 1.69 s**, and the resident view JSON (server-side only, never sent to the browser — decision 18) **4.48 MB → 9.03 MB → 18.1 MB** [measured 2026-09-09, release build, in-memory synthetic capture]. Both grow somewhat worse than linearly with row count, which is what decision 18 said raising the cap would come down to once the transfer itself was fixed. The `/bins` payload at a 1,170-wide reference grid stayed small at all three points (165 KB, 180 KB, and 1.5 KB at 1M — smaller there because spans merge solid at that grid's resolution once the window gets wide enough), so decision 18's payload bound holds past 250k as well as at it; it is decode time and resident memory that make raising the cap a cost, not the payload. **Kept at 250,000** with this measurement as the reason. What is now unknown, if the cap is revisited: whether 1.69 s of server-side decode is acceptable against whatever answers `/study/{id}/streams` (unmeasured — nothing here times the request path, only `parse` itself), and the same three points should be re-measured rather than trusted indefinitely once that is known.

- **A signal mismatch still has nowhere durable to land, so a declared-but-wrong signal shows up in the Topology tab or nowhere.** Closed upstream as not-needed-yet under a two-part trigger; **half of it has fired** — signals are declarable through this tab, which is the only surface for it — and the other half has not, since there is still no wire and no bridge. The consequence is carried by the row's own carrier cell ("not enumerated on Core right now" against a declared serial nothing answers to) rather than by the alert list.

- **The stale-prefix drop has never met a real stale prefix** (decision 19). It is built and tested against crafted fixtures in both signs, and the case it exists for — the **18 records** a real capture opened with, buffered inside the USB-UART bridge past `embarch-core`'s open-time purge — has not been replayed through it. **Hardware debt, the owner's own session:** run a study on the bench, open its Trace tab, and check the axis note reports a dropped prefix where the capture previously fell to the millisecond clock. Until then the `STALE_PREFIX_MAX_ROWS` bound of 512 is an assumption about a bridge FIFO nobody has measured, and the four conditions are known to be *sufficient* to leave good captures alone but not known to be *necessary* to catch the real one.
