# embarch-ui decisions: The Study Designer's panels

**Status:** active, 2026-09-19.

How the tab is laid out, and the one rule that keeps a panel from showing the study before last. What a study *says* — the version fields, security, the declared GATT — is in [study-designer.md](study-designer.md); which firmware repo is open is in [project.md](project.md); GATT capture and its pickers are in [gatt-capture.md](gatt-capture.md).

Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 41 — One apply-study path, build options behind a button, static analysis as a thing you ask for

Four changes from one bench session with the tab's author — one defect, three layout — with one cause: **a panel written to only on the path that happens to know about it.**

**Every field is assigned on every load, from the study or from a default.** "New study" set only the rows and taps, so after opening a saved study it left that study's version requirements, build selection and log level in the panel, and **the first save would have written them back out.** There is one `sdApplyStudy`, and **New study is a load**: the route already writes a valid, runnable `Study`, so the browser loads that file rather than approximating it, and the two paths cannot drift. The invariant is the assignment, not the reset: *a field restored only when the study carries it is the same bug waiting for the next property added to `Study`*.

**The two requirement fields, the Build card and the dev-bench log level moved into a "Build options…" dialog**: all are properties of the saved study, set once then read, and took about a third of the page. **A one-line summary stays** — `dev-bench v9 · DUT any · no build · log level Warn` — or *what does this study require?* needs a dialog to answer. It states what the **study** says, never what the picker shows: an untouched log-level select shows the server's default, which the file does not assert.

**Reading the firmware's source is an action with a result, not a side effect.** The static GATT extraction ran lazily when another panel first needed a characteristic name, cached for the open project, logging failures where nobody would see them. A **Static firmware analysis** submenu on the project panel now holds the extractor name, a **Run GATT extractor** button that discards the cache and re-runs (serving the cache would make the button do nothing after one press, and editing firmware is what changes the answer), the live **Discover GATT** beside it, and what was read: services, characteristics, their C identifiers and declared properties. **"Nothing was read" and "an extractor ran and failed" stay different answers all the way to the browser**, or *static analysis found nothing* means both "there is nothing" and "nobody looked". *(Decision 51 removed the third state, "nobody configured one".)* The first press surfaced a silent extractor failure (`unrecognized characteristic-properties token: WDS_CHRC_TX_PROP`), **fixed by [embarch-study-designer](../../embarch-study-designer/decisions.md) decision 78** — which is what this panel is for.

**The four trailing cards became one panel, "Define the wire"**: stream taps, detected-but-unregistered characteristics, `.eap` protocol manifests, and registered actions and payload layouts — four subjects stacked below the step table instead of the one question they answer, *what goes over the link and what the bytes mean.*

**"New study" names nothing, so it is never refused for a name it invented.** Making it a load exposed what it always sent: the **Study name** box, holding the *open* study's name — so after reading a saved study it got `409 'alpha-study' already exists — open it, or pick another name`, a refusal about a decision nobody made. A name now travels only when somebody typed one (the box differs from what it was last filled with); otherwise the route picks the first free `untitled-study`, `untitled-study-2`, … and cannot refuse. **The `409` is not weakened** for a typed name that collides, since that one protects existing work. **A uniquely-created study is named after the slug it landed on, not the base asked for**: otherwise two files both say `untitled-study`, and saving the second writes to the first one's slug — the overwrite the refusal exists to prevent.

### 51 — There is one extractor, so there is no field: the panel keeps the button and loses the text box

Raised by the repo owner reading the panel: *"I don't understand what we need in that field — the static extraction is the main way to gatt discover and to get all the names of the GATTs. We should only have a run gatt extractor button, no text field."*

**A configuration option with exactly one legal value is not a choice, it is a spelling test.** Two text boxes — one in decision 41's submenu, one in the Open-project dialog — took the name of a `GattConfigExtractor` to run, and the build ships exactly one ([embarch-study-designer](../../embarch-study-designer/decisions.md) decision 33). Everything the field could do was wrong: left blank it silently disabled the only source of characteristic and service *names*, and filled in wrong it answered `unrecognized static extractor`. **It had already cost one bug of its own** — the refusal text and the match arm disagreed about how the single value was spelled, so the only way to learn the right name was to read the Rust.

**Names are not a garnish, which is why the off state had to go.** A live `GattDiscover` returns ATT responses and **ATT carries no names**; the vendor table covers published UUIDs, and on a real DUT nearly every UUID is custom. So an unconfigured project renders every picker, tooltip and dialog group header as a hex UUID head — **the exact state decision 16 exists to have fixed.** A blank text box was one keystroke away from that at all times.

**What replaces it: nothing.** The extractor runs lazily against whatever repo is open, cached per project exactly as before, and **Run GATT extractor** still discards the cache and re-reads — **decision 41's whole point is untouched**, since it was about the extraction being an action with a visible result, not about naming it. The name is still *reported* by the panel, because *which extractor read this repo* is part of what was read; it is simply no longer *asked for*.

**The state that disappears is "no extractor configured", and it was a third answer the code carried everywhere.** `run_static_extraction` returned `Result<Option<_>, _>`, the response carried a `configured` flag beside its `error`, and `RecentProject` stored a per-repo extractor name so reopening a project restored it. All of that collapses: an extraction now succeeds with a table, or fails with a reason. **"Found nothing" is still reachable and still distinguishable** — a repo with no C source is [`NoSourceFilesFound`](../../embarch-study-designer/decisions/gatt-extract.md), an error naming what it looked for, which is the same refusal decision 57 chose over a plausible-looking empty table.

**A `static_extractor` key in an older config file or recents list is ignored, not refused.** Both deserialize non-strictly; rejecting the file would throw away the recents of everyone who had one, over a key that no longer decides anything.
