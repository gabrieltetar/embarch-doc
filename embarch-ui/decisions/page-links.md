# embarch-ui decisions: A link into the page

**Status:** active, 2026-11-24.

Split verbatim from [shell.md](shell.md) (`tasks/ui/114`): decisions 58 and 59, a fragment that names what its tab shows and the tile dialog's hours. Index: [../decisions.md](../decisions.md). Current truth: [../spec.md](../spec.md).

### 58 — A link into the page selects what it names

**A fragment may carry what its tab should show, `#<tab>?<query>`** (2026-10-25): `#desk?item=<work item id>` scrolls to and marks that card; `#live-study?study=<id>` opens that study through the same path the id box takes, live or from disk; `#topology?board=<…>` marks every role box and catalog row that matches a role's slot or label, the board type a role holds, or a catalog board type — case-insensitively, and only then by the board's own name before a `/` or `@`. *Since phase 4 a role box is a part on the canvas (94).* They exist for `embarch-chat`'s step links (`embarch-chat` decision 87): **a link that lands on the tab but not on the thing makes the reader search.** This amends 31's consequence that a fragment names a tab and nothing else, which held because `#trace?study=` addressed a view that no longer existed; 4 always let a fragment carry parameters where a section needs them, for its reasons still: one mechanism, and a fragment never reaches the server.

Read on load and on `hashchange` and handed to the tab as an `embarch:route` event, **the parameters are then taken off the address** (`replaceState`): a link into an already-open page fires only `hashchange`, so following the same link twice would otherwise do nothing. The tab name stays, so a reload lands on the tab and marks nothing again. **A mark stays until the reader clicks or types**, not for a fixed few seconds — the browser may come forward long after the link was followed. **What the tab does not show** — an archived card, a study Core does not have, a board on no role — leaves the tab as it is and says so in one notice line. A value is decoded once by `URLSearchParams` and only compared, put in `textContent` or re-encoded, never put into markup or a selector. Plain and retired fragments behave as before. **Rejected:** the query string (4), parameters left in the address, a mark that fades on a timer.

### 59 — The tile dialog sends hours only when a person changed them

**`PATCH /tiles/{id}` carries `hours` only if the field was edited away from its prefill, and `"hours": null` only after *Use computed*** (2026-10-26). The prefill is the tile's current `hours`, not something typed; sending it on every Save, Polish, Add line and ✓ froze each opened tile as a user override, which `embarch-desk` decision 61 now reads as "a person typed this", so decision 57's self-close never applied to it. *Use computed* sits beside the field, puts `computed_hours` in it and marks the clear; typing again cancels the mark. The tile JSON does not say whether an override exists, so the button is always offered. **Rejected:** clearing by emptying the field (an empty number input is also what a half-typed value looks like).
